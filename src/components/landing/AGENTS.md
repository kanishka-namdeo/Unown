# Landing components (src/components/landing/)

## Purpose

Every band of the marketing page: the hero, the learning loop, the capability dex, mission control, the proof panes, the Unown alphabet, the FAQ, the shipping rail and the finale — plus the shared primitives, effects and generated data they render. This doc is the authority on the page's structure, its palette, its honesty rules and its verification gates; the research behind the decisions is `docs/landing-research.md`.

## Ownership

- Owns: every file in `src/components/landing/` and this doc. The composition root (`src/app/page.tsx`), layout and stylesheets are the parent's (`src/AGENTS.md`); `src/components/ui/accordion.tsx` is the parent's vendored primitive.
- The tracked media under `public/landing/` (OG images, `creatures/`, `tui/`) is rendered by these components but captured/generated by the `scripts/` lanes — see `scripts/AGENTS.md`. Never delete or hand-edit media assets; regenerate through the owning lane.

## Local Contracts

**Structure — ten bands, one file each, order is the argument:**

1. `hero.tsx` (psychic) — h1 "The terminal coding agent that remembers." + the signature subhead, the `BetaBadge` in the kicker row + the plain-language beta sentence under the subhead (one status, two halves: chip + words), the `Seal`, `InstallPanel` (OS-tabbed; default = newest stable release binary; `detectOS()` pure UA sniff, server default macOS), three collapsed `<details>` expanders (agent delegation prompt, source install sequence, CLI command surface gated against `cli.ts` HELP), `PREREQS`, trust strip, `SessionReplay`.
2. `loop.tsx` (leaf) — how it learns: three tabbed beats (Work/Learn/Dream), each body a literal gated artifact (note template from `termhooks.ts`, log lines from `harness.ts`, real memory lines) + the terminal-vs-engine pair strip rendering generated `ENGINE_JOBS`.
3. `dex.tsx` (magma) — the capability dex: one numbered spine, FRLG two-pane listbox (roving tabindex, selection follows focus, fuse.js search scoped to the active screen), screen selector, detail pane mounts ALL entries (inactive `hidden`), lazy posters (`data-poster`), **webm-first sources with a one-shot mp4 fallback on a media `error`** (a decode error on Chromium does not walk to the next `<source>`, and hardware VP9 decoders can reject these streams — the visible reel swaps to its `data-mp4` sibling once and resumes), synthesized Web-Audio cries (forms only), `#dex-<id>` deep links via `history.replaceState`, the `/split*` display-command table (its own gated `COMMANDS` array — `parseCommands` in the claims gate reads the FIRST `const COMMANDS`, so this file carries exactly one).
4. `showcase.tsx` (gold) — mission control: framed real `unown dashboard` PTY stills from `public/landing/tui/dashboard/stills/`, the twelve-surface `SCREENS` list, the addons strip (from `addons-data.ts`). Dashboard affordances point at in-page anchors only — the web dashboard is retired (D7).
5. `live-demo.tsx` (aqua) — the agent-built apps, running live: a switchable GALLERY (the commerce round, the v0-templates pattern — one live deployment per artifact). Each app iframes its own route in browser chrome: `/demo` (Sigil Focus — `docs/live-demo-session.md`), `/bazaar` (Sigil Bazaar — `docs/bazaar-demo-session.md`), and `/cadence` (Cadence — `docs/cadence-demo-session.md`), one persistent iframe whose src swaps on the switch (a same-origin navigation, never a remount). Lazy mount via IntersectionObserver + per-app poster from `scripts/landing_demo_poster.mjs` (shoots EVERY app in one pass; output paths mirror the data file's declared poster paths — committed assets never move), never an idle-visit hydration cost. A working per-app reset (postMessage handshake `{source: "unown-landing", type: "<app>-reset"}` — `sigil-reset` / `bazaar-reset` / `cadence-reset` — the demos listen for in embed mode; the landing pins `targetOrigin` to `window.origin`, NEVER `"*"`), a full-screen escape hatch per app, and receipt chips that swap with the tab (from `live-demo-data.ts`, the addons-data pattern — counts pinned by test, receipts in each app's session record). Below `sm` the frame is replaced by the active app's poster + a tap-through link to its route — a 390px iframe of a storefront is a punishment, not a demo (all three apps collapse to tabs/sheets there). The apps live in `src/app/demo/` + `src/components/sigil/` + `src/lib/sigil/`, `src/app/bazaar/` + `src/components/bazaar/` + `src/lib/bazaar/`, and `src/app/cadence/` + `src/components/cadence/` + `src/lib/cadence/` (route-scoped stylesheets in each route's `globals.css`; the landing page never downloads either). All three demo routes carry CSP `frame-ancestors 'self'` + `X-Frame-Options: SAMEORIGIN` (`next.config.ts`); the bazaar order POST and the cadence checkoff POST are rate-limited per IP (per-lambda-instance semantics). Contrast rule learned the hard way: NO translucent text/background tokens on the chrome bar — axe computes the effective contrast THROUGH alpha (`bg-ink/15` read 1.73:1); opaque pills on full-strength tokens only.
6. `proof.tsx` (magma) — one tabbed band, three panes (Benchmarks / Integrity / Models), all panes stay mounted with `hidden` so generated numbers stay in the SSR DOM for crawlers and gates.
7. `alphabet.tsx` (psychic) — the identity: 28-tile glyph wall, decode panel driven by `LEXICON_BY_ID`, the static Z highlight card (lore reachable without clicking), non-affiliation one-liner.
8. `faq.tsx` (gold) — seven skeptic questions through the vendored Radix accordion; `faq-data.ts` is the one source for BOTH the accordion and the FAQPage JSON-LD.
9. `changelog.tsx` (aqua) — the shipping rail: fixed-height horizontal band, native scroll only, `MAX_LISTED = 1` titles then "+N more" (the valve that keeps the rail inside the scroll budget — see the comment at the constant for the 5→3→2→1 history), `▶` marks the newest cut stop, all numbers read off data; **the rail renders CUT stops only** — an uncut `[Unreleased]` tile spends its whole chrome (`UNCUT`, `no tag yet`, a tally) plus a headline for work that has not shipped, buys the band no part of its argument (the dates carry it), and would cost the word budget ~20 at every changelog entry, so the in-flight record lives where it belongs: the exit's CHANGELOG.md link. The band's exit ("the full record") links CHANGELOG.md, GitHub Releases and the blog — the longhand lane of the same record.
10. `finale.tsx` (leaf) — the last ask + the `Spellbox` toy, CTA links, Konami receipt.

`shell.tsx` owns the shared chrome (`Nav` + `NAV_ENTRIES`: every entry in page order, tagged `primary` (the four argument links — How it learns, Capability dex, Proof, FAQ) or `more` (the four record surfaces — Dashboard, Alphabet, Changelog, Blog) which fold behind the desktop `NavMore` disclosure; the below-`lg` section menu renders all eight flat, never nested — path-refs render through next/link, anchors stay plain `<a>`; the `BetaBadge` the header wordmark and the hero kicker both render (one component, two badge homes; the footer's "Currently in beta." line is the third, word-only — the wordmark carries no tagline, the H1 says it); `Footer`, which takes an optional `anchorPrefix` so the blog routes can render it with its in-page anchors resolving to the landing page, and whose link grid carries the eighth cell — the `/blog` link; `ThemeToggle` auto→light→dark persisting `unown-theme`; `TerminalWindow`; links; `SectionHead`; hue/tone helpers). `effects.tsx` owns `LandingStyles` (the `<noscript>` restore that undoes framer's inline `opacity:0`), `LetterRainProvider`, `AlphabetWakeProvider`, `useKonami`. `LandingMotion` (shell.tsx) is the ONE place framer reduced-motion is handled (`reducedMotion="user"`).

**Data — three files are GENERATED, never hand-edit (each carries the header comment):**

| File | Generator | Source of truth |
|---|---|---|
| `changelog-data.ts` | `scripts/landing_changelog.mjs` | `CHANGELOG.md` headings (`[Unreleased]` stays undated; buckets normalize to Keep-a-Changelog six + `Behavior`) |
| `benchmarks-data.ts` | `scripts/landing_benchmarks.mjs` | receipt JSON under `benchmarks/` (canonical run resolved per model: newest `rerun-*` wins, else base; a figure with no receipt is `null`, never a guess) |
| `engine-data.ts` | `scripts/landing_claims.mjs` | `JOB_DEFS` in `pi-repo/packages/self-learning/src/router.ts` |

Every quoted engine literal on the page — `integrity.tsx` LOG rows, `loop.tsx` BEATS bodies, `hero.tsx` COMMANDS + slash chips, the `dex.tsx` `/split*` table — is matched by `scripts/landing_claims.mjs` against the writing sources (`hooks.ts`, `termhooks.ts`, `harness.ts`, `instruction-guard.ts`, `cli.ts` HELP, `splitview.ts`); the gate is one-directional (page implies source; HELP is deliberately a superset).

**Authored data (hand-maintained):** `dex-data.ts` (append-one-object `RAW`; numbers stamped from array position — never typed; `Capture` = video|still|pending with `PENDING` the honest empty stage), `faq-data.ts`, `lexicon.ts` (28 entries; `lore` verified against Bulbapedia/PokemonDB/Wikipedia/ssbwiki only; `means` a DECODE <= ~12 words, never a spec), `addons-data.ts` (mirrors `addons/config.ts` leaf keys — the test suite drift-pins it), `benchmarks.tsx`'s derived `LIFT_SCALE`/`COLD_BAR_W`.

**Creatures and glyphs:** `creature.tsx` renders the feature creatures (authored pixel art — never Pokemon assets, never a named species; decorative by default, height-locked to 64px multiples, `image-rendering: pixelated`); the sprites under `public/landing/creatures/` are written by the deterministic pipeline (`scripts/creature_*.mjs` — the script is the art). `glyphs.ts` holds the 28 hand-authored Unown stroke-path forms; `glyph.tsx` renders them with palette tokens via CSS vars — no hand-picked hexes (that is what keeps `gba_palette_check.mjs` honest). The dex is the one canonical home for creatures (pinned by test).

**Vendored:** `provider-marks.tsx` is generated from pinned CC0 Simple Icons by `scripts/vendor-provider-marks.mjs` — never hotlink, never `npm i simple-icons`; OpenAI/Agnes/llama.cpp are text-only by design.

**Honesty rules (the page is part of DOX):** every number is checkable against a committed receipt; suite names by path, never counts; unmeasured figures print "not measured"; the page says plainly it is an independent project (the Footer notice); no `aggregateRating` in the JSON-LD (`seo.tsx`); a claim that contradicts the code is the same defect as a stale doc line — cut the claim, never invent a replacement figure.

**Motion and a11y:** the base state of every animated rule is the finished state (reduced-motion = everything renders complete); reveal animations animate `transform`/`scaleX`, never `width`; only user-initiated playback is announced; tabs/listboxes follow WAI-ARIA patterns with roving tabindex; exactly two live regions on the page.

## Work Guidance

- Scroll budget contract: <= 13.5 viewports, <= 3,320 words, no top-level band > 3 viewports at 1440x900. Amended three times on 2026-10-28: the live-preview round (13 / 3,200 → 13.5 / 3,250) carried the page's first interactive-application frame (68 words / 1.09vh, every other band kept its height); the commerce round (3,250 → 3,290) carries the second frame AND the rail's structural cost — every release stop adds ~30 generated words to the changelog band (title + tally + chrome, never deletable per the compression contract). The gallery's own chrome was compressed first (measured 3,308 → 3,282 before the amendment; the band reads 47 words / 1.1vh — the switcher, per-app receipt chips and reset are the frame's, not prose). The cadence round (3,290 → 3,320) carries the gallery's third app (its receipt chips are data, not prose) and the 0.0.35 stop's own generated chrome — the newest stop's rail title swapped in measured 3,306 (24 over), the round's own listed title compressed first. Never settle a breach by deleting a generated number or a gated literal — compress (tabs, expanders, cut restatements).
- **The header carries exactly one filled action** (`Get started` → `#quickstart`); everything else in it is link-styled or icon-styled. That is the anti-crowding invariant, not a taste call: the bar ran eight labels beside the CTA and read as a wall of CTAs. A fifth `primary` nav entry means re-measuring the bar at 1024px (the width the eight-label version filled), and new entries default to the `more` group.
- Palette contract (GBA Generation III): 5-bit grid, dual-declared identical light scheme, no hand-picked hexes in components, AA 4.5:1 for text tokens on every surface in both schemes.
- A scroll-budget or palette change regenerates the tracked `public/landing/*.png` OG shots via `scripts/landing_og_shots.mjs` (it asserts `--color-canvas === #102039` before shooting).
- A new dex entry moves the tallies and every count pin in the test suites with it; a new filmed capture moves `dex-media.test.tsx`'s expectations.
- Voice: concrete, confident, honest about limitations; game-voice original words for dex copy; no emojis; no Pokemon-release assets reproduced.

## Verification

- `bun test src` — the component suites pin the structure: composition root (9 bands, hue walk, anchors), dex (22-option listbox, derived numbers, deep links, pane contract, lazy posters, no autoPlay), dex-media (every media path exists, `<img>` dims match the PNG's real IHDR, mp4 faststart, webm EBML), loop, changelog rail, quickstart, landing-copy (h1, install lanes, dashboard links stay in-page, the bar's four primaries + the `NavMore` disclosure's four record entries, integrity receipts, models local lane), creature (one home, decorative a11y), addons drift, benchmark figures/lift.
- `bun run check:changelog` + `check:benchmarks` + `check:claims` (CI) — the generated-data gates; regenerate with the same scripts (no `--check`).
- `bun scripts/gba_palette_check.mjs` (CI) — the palette gate; `bun scripts/check_theme.mjs` — the TUI theme schema gate.
- `bunx playwright test` (CI e2e) — axe-core WCAG A/AA zero-violation in two motion passes, the scroll budget, the dex video decode gate (including the blocked-webm → mp4 fallback case), the SEO surface.
- Against a production build: `bun scripts/landing_shots.mjs` (both schemes + reduced motion + mobile), `bun scripts/contrast_audit.mjs` (every visible text node, both schemes), `bun scripts/theme_toggle_check.mjs` (toggle state, localStorage, reload survival), `bun run audit:landing --budget`.
- Optional design critique: `bun run review:vlm` (Agnes VLM lane) — a reviewer's aid, not a gate.
