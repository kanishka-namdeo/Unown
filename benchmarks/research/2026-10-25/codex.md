# OpenAI Codex CLI — Competitive Research (R2)

**Date:** 2026-10-25 · **Codex version researched:** `codex-cli 0.164.0` (released 2026-10-23, latest stable) + `main` branch (`rust-v0.165.0-alpha.1`). Unown compared at v0.0.15 (pi-repo fork).

**Method note:** `developers.openai.com` returns 403 (geo/IP-blocked) and `web.archive.org` is unreachable from this sandbox, so every *current-state* claim below was verified against (a) the **shipped v0.164.0 Linux binary** (downloaded from GitHub Releases; every subcommand's `--help` captured and quoted), and (b) the **`main`-branch source** (full repo tarball from `codeload.github.com`). Full prose documentation was recovered from the last tag that still shipped real docs (`rust-v0.58.0`, `docs/config.md` 53KB etc.) — today's repo `docs/*.md` are one-line stubs linking to developers.openai.com. Release-notes history (0.155→0.164) was extracted from the GitHub releases pages. Nothing below is invented; where a feature is *removed* in current Codex that is explicitly stated.

**Headline changes vs. common knowledge (2025-era Codex):**
- Approval policy surface **shrank**: `-a/--ask-for-approval` now accepts only `on-request | never` (binary-verified: `codex -a bogus` → `[possible values: on-request, never]`); `untrusted`/`on-failure` are legacy config values, superseded by a `granular` approval config and named **permission profiles**.
- `--full-auto` and `--yolo` are **gone**; replaced by `--approve-for-me` (Guardian auto-review) and `--dangerously-bypass-approvals-and-sandbox`.
- `/approvals` is renamed **`/permissions`**; `/undo` is replaced by **Esc-Esc transcript browsing + Enter-to-rewind (backtrack)**.
- The `~/.codex/prompts/*.md` custom-prompts library (`/prompts:<name>`, `$1`–`$9`, `$ARGUMENTS`) was **removed from the TUI**; the shipped alternative is **`/presets`** — ten numbered slots persisted under `[tui.presets.<1-10>]` in config.
- Linux sandbox moved from Landlock to **bubblewrap + seccomp** (bwrap binary shipped with Codex; Landlock only via legacy feature flag); Windows uses restricted-token/MXC sandboxes; macOS stays Seatbelt.
- Sessions live in a **SQLite thread store** with `codex migrate-rollouts` for legacy rollout files.
- 182 feature flags via `codex features list` (stages: stable / experimental / under development / removed).
- Session storage/management grew: `codex queue`, `codex archive|delete|unarchive <id|name>`, `codex agents` (Command Center, pin with `p`), `codex exec resume|fork|review`.

## Top gaps (ranked for Unown's existing features)

Ranked by (user-workflow value × fit with Unown's existing surface). Effort: S < 1 day, M ≤ 1 week, L > 1 week.

### 1. Headless `-p --json` per-event stream + `-o` last-message file — **MISSING** (effort **M**)
- **Rationale:** Unown's exit contract (0/1/2/3/4) and envelope are great for "run once, get answer" but unusable for CI dashboards that want progress, tool calls, and token accounting per event. `codex exec --json` is the single most-cited automation surface in Codex; every Codex SDK/pipeline story starts with it. Unown already streams internally — it just doesn't expose it.
- **Sketch:** new `pi-repo/packages/self-learning/src/exec-events.ts` mapping pi session-bus events → JSONL (`thread.started`, `turn.started`, `item.*` with `command_execution`/`file_change`/`mcp_tool_call`/`todo_list` payloads — mirror Codex's exact schema so scripts port over); wire through `output-format.ts` behind `unown -p --json`; add `--output-last-message <file>` in `cli.ts` headless path; keep the final envelope as the last JSONL line (backwards compatible).

### 2. Launch-time interactive resume picker with transcript preview + `--all` — **INCOMPLETE** (effort **M**)
- **Rationale:** Unown forces users to know an id/name (`--resume` errors "bare picker: run `unown` and use /resume"). Codex's `codex resume` opens a **cwd-filtered, paginated picker with a live transcript preview** — the "which session was that?" moment is the highest-frequency resume pain. Unown already has the picker in-session (pi) and a session catalog (`sessions.ts`); only launch-time plumbing + preview is missing.
- **Sketch:** extend `pi-repo/packages/self-learning/src/resume.ts` with `interactive: true` mode when `--resume` is passed with no argument: reuse pi's picker component (tui/src/components) seeded from `sessions.ts` catalog; add Cwd/Repo/All filter modes (project-identity.ts already fingerprints repos); render a tail preview by streaming the last ~20 events from the session JSONL (same bounded reads resume.ts already does: 4KiB header / 512KiB tail). Add `--resume-last` alias for `-c` and `--resume-all` (drop cwd filter).

### 3. Headless `unown review` with `--uncommitted/--base/--commit/--title` — **INCOMPLETE** (effort **M**)
- **Rationale:** Unown has a strong in-session `/review` (incl. PR URL via gh), but nothing for `pre-push` hooks or CI. Codex ships `codex review` + `codex exec review` with exactly four flags that cover staged/unstaged/untracked, a base branch, a single commit, and a display title. Same session engine, trivial CLI surface = high leverage for Unown's "self-improving CI" story (benchmarks/blueprint already run headless).
- **Sketch:** promote `review.ts` + `pr-review.ts` into a CLI subcommand in `cli.ts` (`unown review [--base <branch>] [--commit <sha>] [--uncommitted] [--title <t>] [instructions...]`); reuse the `-p` headless runner (runner.ts) with a review system prompt; add a review-specific exit code (e.g. 0 clean / 5 findings) to the existing exit contract.

### 4. `/diff` in-session git diff view — **MISSING** (effort **S**)
- **Rationale:** "What did you just change?" is a per-task reflex; Codex's `/diff` ("git diff including untracked") is in the top third of its command popup ordering. Unown has checkpoints and `/receipts` but no quick visual. `gittools.ts` already wraps git.
- **Sketch:** new command in `pi-repo/packages/self-learning/src/gittools.ts` (register `/diff` alongside existing commands via the same registration path used by `/commit`): `git diff HEAD` + untracked-file listing, render in pi's pager overlay; optionally accept `/diff <path>` and staged-vs-unstaged toggling.

### 5. `/status` in-session card — **MISSING** (effort **S**)
- **Rationale:** Codex's `/status` answers "what model/effort am I on, what can it do without asking, how much context is left" in one keystroke — including the AGENTS.md sources actually loaded. Unown spreads this across `/context`, `/permissions`, `/providers`, and the dashboard.
- **Sketch:** new `pi-repo/packages/self-learning/src/status-card.ts`: model+effort (model-specs.ts), permission mode + trust state (permissions.ts, config-trust.ts), token usage + context-window remaining (budget.ts already tracks), loaded instruction files (project-identity.ts), loop-guard/max-turns state. Render via pi markdown; no new deps.

### 6. Named permission profiles with inheritance — **MISSING** (effort **M**)
- **Rationale:** Codex's `[permissions.<name>] extends = ":workspace"` bundles let users ship per-project sane defaults ("review-safe", "nightly-fleet") and switch via `/permissions` or `default_permissions`. Unown's allow/deny/ask rules are strong but anonymous and flat; profile selection would let Unown's `--permission-mode` (default/acceptEdits/bypassPermissions) become project-declared instead of global enums.
- **Sketch:** extend `pi-repo/packages/self-learning/src/permissions.ts`: add `profiles: { [name]: { extends, description, rules } }` to `.unown/permissions.json`; resolve inheritance at load (cycle-detect like codex's `resolve_profile`); add `defaultProfile` key + `/permissions <profile>` inline arg; CLI `unown permissions apply <profile>`.

### 7. Queue + steer: `unown queue --session <id|name> --message` and follow-ups mid-run — **MISSING** (effort **M**)
- **Rationale:** Codex's `codex queue` sends a message to an existing (possibly running) session, and 2026-Codex added steering ("send a follow-up while responding"). For Unown's async fleet (`/tasks`, task_control) the same UX for the *primary* session is missing — long routines/watch runs currently can't be nudged.
- **Sketch:** the engine already accepts posted messages (fleet-runtime.ts); add a queue file per session in the store (outbox pattern already exists in `outbox.ts` for notes — generalize it to `messages.outbox/`), a `queue` subcommand in `cli.ts`, and an in-TUI "queued follow-up" affordance in the composer when a turn is active (pi's input queue: tui bottom pane).

### 8. `-c key=value` config overrides + `unown features list|enable|disable` — **MISSING** (effort **S/M**)
- **Rationale:** `-c` is how every Codex power user pins a model or relaxes a sandbox per-invocation without editing files ("`-c model_reasoning_effort=high`"), and `codex features` makes experimental surface discoverable. Unown's equivalents require editing `.unown/settings.json`. This also unlocks profile-style presets (`-c` + a named layer file ≈ Codex `-p <name>.config.toml`).
- **Sketch:** new `pi-repo/packages/self-learning/src/config-overrides.ts` (JSON dotted-path setter applied after project-settings.ts load; reject unknown keys → feeds exit-code 2); optional `unown features list` reading a static feature table (self-learning feature registry) with `--enable/--disable` writing settings.

### 9. Session archive/delete/unarchive CLI + `/archive` — **MISSING** (effort **S**)
- **Rationale:** Codex treats the session store as a mailbox: `archive <name>`, `delete --force`, `/archive`, `/delete` keep the resume picker clean. Unown's picker (and `-c` latest-match) grows stale over long-lived projects; `sessions.ts` already has the metadata.
- **Sketch:** `sessions-cli.ts`: `unown sessions archive|unarchive|delete <id|name>` writing `archived: true` into session_info (resume.ts already scans this header — teach `latestSessionForCwd` and the picker to skip archived); pi command registration for `/archive` `/delete`.

### 10. AGENTS.md loading upgrades: `AGENTS.override.md` + fallback filenames + root markers + byte cap — **INCOMPLETE** (effort **S**)
- **Rationale:** Three small loader wins from Codex's `agents_md.rs`: (a) `AGENTS.override.md` lets users keep upstream AGENTS.md unmodified in vendored repos; (b) `project_doc_fallback_filenames = ["CLAUDE.md", ...]` makes migrated repos work before rewrite — a natural companion to `unown import`; (c) 32KiB cap prevents context blowups from huge instruction files; (d) skip instructions entirely for untrusted projects (prompt-injection hardening). Unown's own repo uses a DOX hierarchy — this fits its grain.
- **Sketch:** extend the instruction-assembly path in `pi-repo/packages/self-learning/src/` (where AGENTS.md/repo docs are ingested for prompts — instruction-guard.ts/project-identity.ts): per-directory resolution order override→AGENTS.md→fallbacks (fallbacks from `.unown/settings.json`, default `[]`), root→leaf concat with 32KiB default cap (`instructionMaxBytes` setting), and honor config-trust verdict (untrusted → skip project docs).

**Honorable mentions:** `/recap` (on-demand summary without compaction — thin wrapper over auto-compact's summarizer; S); `--ephemeral` headless flag (S); image input `-i` + paste (M, needs VLM wiring Unown already has via llm-bridge); `/statusline` + `/title` configurable items (S); elvish completions (trivial); `codex exec fork <id>` headless fork (S); per-tool MCP `approval_mode` + `output_token_limit` in `mcp.ts` (M); OTEL export for enterprise parity (L, low demand for Unown's audience).

**Where Unown is already ahead (keep + advertise):** richer headless exit contract (0–4 + loop guard) vs Codex's 0/1; `unown update` rollback+pin vs Codex's none; `unown import` breadth (5 agents) vs Codex's 1 (but Codex's per-item selection UI + sessions/skills/hooks migration is deeper — see #Top gaps); `unown mcp test`; custom commands with `${N:-default}` defaults (Codex removed its equivalent); `/btw` overlay (zero-context, vs Codex's fork-based `/btw`); 4-tier memory + versioned rollback vs Codex's rollout-mining memories; dashboard/engine ecosystem (Codex has nothing like it locally).
