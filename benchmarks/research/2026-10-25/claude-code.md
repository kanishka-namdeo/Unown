## Top gaps

Ranked for value against Unown's **existing** features (a gap only matters here if it completes or fixes something Unown already ships).

1. **In-session `/usage` + `/cost` command (with per-model breakdown & prompt-cache stats)** — *INCOMPLETE → the single cheapest high-value fix.* Claude users check cost dozens of times a day without leaving the session (`/cost`, `/stats` aliases); Unown forces `unown usage` from another terminal or the 11-screen dashboard. Story: mid-refactor you wonder whether to keep going on the big model — Unown gives you no answer inside the TUI, Claude gives a two-keystroke answer with per-model rows and cache-hit percentages. Sketch: register `/usage` (aliases `/cost`, `/stats`) in the session-command registry in `pi-repo/packages/self-learning/src/boot.ts` (where `/context`, `/blame` etc. register); aggregate from the receipts/telemetry store that `unown usage` already reads (engine usage counters in `usage.ts`/`engine-status.ts`), render a static panel via the existing TUI overlay used by `btw-overlay.ts`; include total tokens/cost, per-model split, cache stats from `packages/ai` usage fields, duration, lines added/removed from receipts. Effort: **S**.
2. **Launch-time interactive session picker + `--fork-session` + `-n/--name`** — Unown's `resume.ts` already computes a newest-first candidate list and even returns "the five newest" on ambiguous names — the picker is one rendering step away. Claude's `claude --resume` with no arg is muscle memory; Unown requiring an argument (and erroring with candidates) is the surprising half. Same launch surface should take `-n <name>` (naming at start) and `--fork-session` (fork-on-resume, matching in-session `/fork`). Sketch: `--resume` with no arg (and `unown sessions list --picker`) → reuse `SessionCandidate[]` from `resume.ts`; render picker in the TUI boot path (`boot.ts` interactive entry, pi list component as used by `/resume`); add `--fork-session` flag in `cli.ts` arg block that, when combined with `-c`/`--resume`, copies the target JSONL to a new session id before open (reuse pi `/fork` copy logic); add `--name` writing the first `session_info` entry (auto-title.ts format). Effort: **M**.
3. **Rewind menu: per-prompt code-vs-conversation restore + `Esc Esc` + "Summarize from here"** — Unown has all the atoms (`checkpoints.ts`, `/checkpoint /undo /redo /restore`, auto-compact) but not the workflow that makes Claude Code's checkpointing famous: one menu, per-prompt rows, six actions, original prompt reloaded into the input. Story: "Claude broke the tests three prompts ago" — Claude users press Esc Esc, pick the prompt, choose *Restore code and conversation*, and re-send the edited prompt; Unown users must figure out which of `/undo` vs `/restore` vs `/checkpoints` applies, and can't restore conversation separately from code. Sketch: extend `checkpoints.ts` to snapshot file state at each user prompt (not just on explicit `/checkpoint`); add a picker overlay (pattern: `btw-overlay.ts`) listing prompts with change counts; actions map to existing `/restore` (code) + a new conversation-truncate path; bind double-Esc in `termhooks.ts` when input is empty; "Summarize from here/up to here" reuses the compaction call in `auto-compact.ts` with a range parameter. Effort: **M**.
4. **Headless `stream-json` output + `--input-format stream-json` + partial messages** — Unown's `-p` envelope is good for run-and-done, but Claude's streaming JSON is what every harness (and Claude's own Agent SDK, ccusage-style dashboards, statusline scripts) consumes. Without it, Unown can't be embedded in IDEs/watchers that want live turns. Sketch: in the print path (`self-learning/src/cli.ts` `-p` branch), emit newline-delimited JSON events (system/init, assistant deltas with `--include-partial-messages`, tool calls, final result = today's envelope) using `packages/ai` stream events; accept `--input-format stream-json` to drive multi-turn from stdin (feed user messages into the same session loop the TUI uses in `boot.ts`). Effort: **M**.
5. **User-scriptable statusline (`/statusline` + `statusLine` setting + `subagentStatusLine`)** — Unown's split-view TUI and fleet/subagent progress already render fixed footers; Claude turns the same slot into an open platform (cost, context %, model, rate limits, git repo — piped as JSON to any script, with `/statusline` generating the script from a natural-language request). Story: a user wants "model + context% + cost" always visible in tmux; on Unown they can't. Sketch: add a `statusline` row component in `packages/tui` footer fed by a JSON snapshot object (model, effort, context %, tokens, cost from receipts, session name — most fields already exist for the dashboard); run user command from `.unown/settings.json` `statusLine.command` on a refresh tick; add `/statusline` session command in `boot.ts` that prompts the model to write the script (Unown's /recipe-style instruction lane can host the prompt). Effort: **M**.
6. **Model fallback chains (`--fallback-model` / `fallbackModel` setting)** — Unown's whole pitch is multi-provider, yet failover lives only in the bridge (upstream switching); Claude's per-session ordered chain ("try sonnet, then haiku") — covering subagents and compaction too — is the obvious multi-model workflow Unown lacks. Story: Opus-tier endpoint is rate-limited at 2am during a routine; Unown's run dies, Claude transparently fails over for the turn and shows a notice. Sketch: parse `--fallback-model a,b` in `cli.ts`; on non-retryable 5xx/404 from `packages/ai` (reuse `provider-retry.ts` classification), swap the model for the remainder of the turn, emit a TUI notice, restore next turn; persist as `fallbackModel` array in `.unown/settings.json` (extend `project-settings.ts` schema). Effort: **M**.
7. **`/effort` in-session command + effort status + `/model` session-only save** — Unown already parses `--effort` and stores effort per-project, but there's no way to check or change effort mid-session without restarting. Claude gives a slider (`Enter` save-default vs `s` session-only) plus `ultracode`. Sketch: register `/effort [level|status]` in `boot.ts` command registry mutating the live `SamplingEffort`/effort option on the session's model config (same knob `--effort` sets in `cli.ts`); show current level in the TUI status area next to the model name; add session-only vs persisted distinction (persist via `project-settings.ts`). Effort: **S**.
8. **Close the hook-event gap + async hooks + `/hooks` upgrade** — Unown's hook system (13 events, 5 handler types, full decision logging) is architecturally at parity, but is missing the events that make hooks *useful around existing features*: `PreCompact`/`PostCompact` (Unown ships auto-compact!), `PostToolUseFailure` (Unown ships a PostToolUse syntax gate), `PreModelSwitch`/`PostModelSwitch` (Unown ships /model), `Notification` (Unown ships notify.ts), `FileChanged`/`DirectoryAdded` (Unown ships /add-dir), `PermissionRequest`/`PermissionDenied` (Unown ships granular permissions), `WorktreeCreate`/`WorktreeRemove` (Unown ships --worktree). Claude also has `async: true` hooks with `asyncRewake`. Sketch: extend the event enum + dispatch in `termhooks.ts` (always-on gate infra already intercepts most of these points — e.g., the PostToolUse syntax gate site can emit PostToolUseFailure); wire Pre/PostCompact into `auto-compact.ts` trigger; Pre/PostModelSwitch into the pi `/model` handler; add `async` field to hook config with background execution (fire-and-forget spawn in the hook runner), keeping the decision log. Effort: **M**.
9. **`/autocompact` window command + idle compaction** — Unown's auto-compact thresholds are env-vars (`UNOWN_AUTO_COMPACT_THRESHOLD`), invisible to normal users; Claude exposes the same knob as a command (`/autocompact 500k`), a flag, and a settings key, plus idle compaction (compact a 200K+ conversation after ~54 min idle so the prompt cache isn't lost). Sketch: register `/autocompact [auto|<tokens>]` in `boot.ts` writing the same value `auto-compact.ts` reads (add a settings-key read alongside the env); idle compaction: in the interactive loop, track last-activity timestamp (already needed for notify), on a 45–60 min idle timer call the existing compaction path when over threshold. Effort: **S**.
10. **Output styles (`/output-style`, built-ins, custom)** — Claude ships Default/Proactive/Concise/Explanatory/Learning plus custom style files; Unown has nothing between "raw AGENTS.md prose" and "full recipes". Concise alone is one of the most-requested styles. Sketch: model as special recipes or a new `outputStyle` key in `.unown/settings.json` + `/output-style` command in `boot.ts` that swaps a system-prompt section (Unown already owns the system prompt assembly for AGENTS.md injection — same site); ship Concise + Explanatory built-ins as bundled recipes. Effort: **S/M**.

Runners-up (worth scheduling but lower value-per-effort): MCP OAuth login/logout + shareable `.mcp.json` project scope (Unown already has `mcp test` Claude lacks); a first-party GitHub Action for `@unown` mentions (complements `-p` and routines; large surface); interactive-mode notifications/idle prompt (extend `notify.ts` beyond print mode — its own header says the TUI is "deliberately skipped"); `Ctrl+R` reverse-history-search (today bound to rename — INCONSISTENT with Claude muscle memory; consider rebinding or adding search to the input handler in `termhooks.ts`); `/terminal-setup`; paste-chip handling; `--max-budget-usd`; plan/execute model routing (`opusplan` analog, natural for Unown's multi-provider presets); path-scoped rules for AGENTS.md (`.unown/rules/` with `paths:` frontmatter — Unown already lazy-loads LSP context, this completes the instruction story); per-agent persistent memory + `isolation: worktree` for fleet agents.
