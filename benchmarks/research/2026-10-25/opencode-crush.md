# Competitive Research: OpenCode + Crush vs Unown

**Task ID:** R4 · **Agent:** opencode-crush-researcher · **Date:** 2026-10-25
**Scope:** (A) OpenCode — sst/opencode → anomalyco/opencode (opencode.ai/docs, V1 current docs + OpenCode V2 current docs + GitHub README/CHANGELOG); (B) Crush — charmbracelet/crush (README + full shallow clone of source tree: `docs/`, `internal/`).
**Method:** 40+ HTTP fetches (33 V1 doc pages, 8 V2 doc pages, sitemap crawl, raw GitHub README/CHANGELOG, path probes) + full source read of the cloned Crush repo. Every capability below cites an official docs URL or a repo file path. Nothing invented; where the task brief guessed a flag that does not exist in the current product (e.g. Crush `--mode`, `--prompt`, `--version`, `--continue` — all disproved, see matrix), the correction is documented.

**Key market context discovered:** OpenCode is now TWO products: **V1** (docs at opencode.ai/docs, `opencode-ai` npm, what Unown reverse-engineered `/init` from) and **V2** (new `@opencode/cli`, desktop app, web app, Console cloud — actively shipping, v2.1.4 released 2026-10-23). V2 **removed LSP entirely**, discontinued **session share**, and moved to an ordered `permissions` array. Crush is at a Bash-config (`crushrc`) stage with hooks limited to `PreToolUse` only, and **no undo**. Unown is ahead of both in several areas (checkpoints/undo, loop guard with exit-contract integration, LSP integration, elicitation policy, hooks breadth, session share w/ redaction).
