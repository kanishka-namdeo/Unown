## Top gaps (ranked, for Unown's EXISTING surfaces)

1. **Per-edit auto-commit + git-native `/undo` pair (aider A1+A2+A3+A4).** Unown already ships `/commit`, `/undo`/`/redo` (checkpoints), `/review`, gittools' hardened git plumbing — but the aider workflow users expect ("aider committed each change; `/undo` rewinds exactly one AI change; my own dirty edits were sealed separately first") is absent: `UNOWN_AUTO_COMMIT` is opt-in and end-of-session only, and `/undo` knows nothing about git. *Sketch:* gittools.ts — add `UNOWN_AUTO_COMMIT=edit` mode committing after each completed turn (message from that turn's assistant text); pre-commit user-dirty state as a separate `unown(pre):` commit (aider's dirty-commit separation); teach checkpoints.ts `/undo` to detect "last commit is unown-attributed AND matches the turn's before-images" and offer `git reset` rewind; add `--attribute-author/--attribute-co-authored-by`-style flags. **Effort: M.**
2. **`/test` + `--test-cmd --auto-test` fix loop (aider A11, extends A10).** Unown's post-edit auto-formatters + hooks syntax-gate already have the plumbing to close the loop aider closes: run tests after edits, feed failures back, let the model fix them. This directly strengthens `/review`, `unown ralph` and routines (which already have retry-max but no semantic test check). *Sketch:* extend formatters.ts to a generic post-edit checks lane (`.unown/checks.json`: `{pattern, command, kind: "format"|"test", scope: "file"|"project"}`); add `/test <cmd>` + `/lint [files]` session commands in tools.ts that run via the jailed exec and, on non-zero exit, append output as a user-visible tool result for the same turn (reuse the PostToolUse gate plumbing). **Effort: M.**
3. **Per-item `/tokens` report + file-context curation `/add` `/drop` `/read-only` (aider A5+A9).** Unown's `/context` shows a utilization bar, but users cannot answer "what is eating my window, and what do I drop?" — the exact question aider's `/tokens`+`/drop` workflow answers. Unown's repomap + memory make a curated file lane synergistic (pin read-only files into the system prompt). *Sketch:* context-viz.ts — enumerate context components (memory, standing orders, pinned files, messages, tool results, repomap) with token estimates and a remaining-window row; add pinned-file store (`.unown/context.json`) + `/ctx add <file> [--read-only]`, `/ctx drop`, `/ctx ls` session commands injected via term.ts's system-prompt lane. **Effort: M.**
4. **Session conversation surgery: `--edit` in `$EDITOR` + edit-in-place/fork (goose G3).** Unown has `/edit-resend` (one message + checkpoint revert) and `/fork`, but the goose pattern (open the whole conversation as YAML, trim/rewrite, continue or fork) is the power-user's tool for rescuing derailed sessions — a natural extension of Unown's session store + trust model. *Sketch:* edit-resend.ts — `/edit-session [--fork]`: serialize session JSONL → YAML to a temp file, spawn `$VISUAL/$EDITOR`, reparse + validate, then either truncate the session store in place or write a new session file (sessions.ts already exposes branch/resetLeaf primitives for this). Add `unown sessions export --format markdown` (goose G2) in the same pass for shareable transcripts. **Effort: M.**
5. **Dual-model architect/editor mode (aider A16+A17).** Unown has `--plan`, `unown ralph --reviewer-model`, subagent routing — all the ingredients — but no chat mode where a strong planner proposes and a cheap/fast editor model applies. This is the highest-leverage cost/quality feature aider has that Unown's single-model plan flow lacks. *Sketch:* llm.ts/model-specs.ts — resolve `editorModel`; runner.ts — new mode where the plan phase runs on main model and the apply phase spawns a subagent (subagent-routing.ts) with the editor model + edit tools, `--auto-accept-architect` mapping to permission-mode bypass; expose `/architect` + `/editor-model`. **Effort: L.**
6. **Recipe `retry{checks,on_failure}` + schedule-a-recipe wiring (goose G9+G11).** Unown's recipes port already parses `sub_recipes`/`response_schema`; goose's `retry` block (shell success checks, on_failure cleanup, timeouts) is the missing third leg — and Unown's routines (which already have retry-max/backoff at the schedule level) can't even *run* a recipe today (`routines create` takes `--prompt` only). *Sketch:* recipes.ts — parse `retry` and wrap the subagent run in run-with-checks (checks via the existing jailed exec; on_failure before re-run); routine-schedule.ts — accept `--recipe <name>` so a routine executes `unown recipes run` per firing. **Effort: M.**
7. **`goose configure`-style persistent TUI configurator (goose G1).** Unown's setup wizard is one-shot; every post-setup change (permission-mode default, hooks, formatters, providers, recipe sources) means hand-editing JSON or remembering five subcommands. Goose's single `configure` menu with type-to-filter is the retention feature Unown's breadth (25+ CLI verbs) most needs. *Sketch:* setup-dialog.ts + providers-command.ts — `unown configure`: enumerate the same knobs `unown doctor` already inspects, write through project-settings.ts/permissions.ts/hooks-config.ts. **Effort: M.**
8. **`/copy-context` + `--copy-paste` web-chat bridge (aider A15, cf. goose G23).** Neither aider's copy/paste lane nor goose's subscription-OAuth ACP providers exist in Unown — meaning users whose only access to a frontier model is a web UI (ChatGPT Plus, Claude Pro) cannot use it as the architect over Unown's repo map. The copy/paste lane is the cheap, TOS-safe version. *Sketch:* new copy-context.ts using pi's clipboard utils — `/copy-context [instructions]` renders pinned files + read-only refs + repomap (repomap/) + instructions as markdown to clipboard; `--copy-paste` mode polls clipboard for a reply and runs it through a headless apply sub-session; wires naturally to gap #3's pinned-file store. **Effort: M.**
9. **Terminal integration `@unown` aliases with shell-history context (goose G21).** `@g why did the last command fail` from the shell prompt is goose's stickiest daily-driver feature; Unown's termhooks already lives in that part of the UX but only does security. *Sketch:* new term-integrate module (mirror of goose `term init`): emit shell script defining `@unown`/`@u` → `unown -p` with the last N history lines + cwd injected; `unown term info` for prompt status; optional `--default` unknown-command fallback. Complements notify.ts (add `UNOWN_NOTIFY_COMMAND` custom lane + TUI turn-end notifications — aider A25). **Effort: S–M.**
10. **`.unown/ignore` for repomap/watch (aider A8) + `/web` command (aider A13).** Small but obvious complements of Unown's ported watch-files/repomap: today vendor/generated paths can't be excluded from `unown watch` triggers or the map beyond .gitignore, and there is no one-keystroke "read this URL into the chat" despite webcache.ts existing. *Sketch:* repomap-core.ts + watch.ts load `.unown/ignore` (gitignore syntax via the permissions layer's patternToRegex); tools.ts `/web <url>` → webcache.ts fetch → markdown message + auto-summarize option. **Effort: S.**

Honorable mentions: markdown/yaml session export + `session diagnostics` bundle (G2/G28); ask-mode/no-write discussion lane (A16 — cheap: permission-mode preset); `--map-refresh auto|always|files|manual` + `--map-multiplier-no-files` (A6); weak-model lane for cheap commit messages/compaction (A18); per-recipe custom slash commands (G30); prompt-template overrides (G32); `/help` self-docs mode (A28) + offline docs (G29); extension allowlist (G13).
