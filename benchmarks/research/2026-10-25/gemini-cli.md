# R3 — Gemini CLI (google-gemini/gemini-cli) competitive research

**Research date:** 2026-10-25 · **Current stable:** v0.64.0 (released Oct 13, 2026) · **Researcher:** gemini-researcher (task R3)

## State of the product (read this first)

- **Deprecation banner on every docs page:** "Unpaid tier and Google One users: Gemini CLI was replaced by **Antigravity CLI** on June 18th, 2026" and "Gemini CLI has not been optimized for Gemini 4 Argon." The repo is still alive (weekly preview Tue 23:59 UTC / stable Tue 20:00 UTC / nightly cadence), but Google is steering users to Antigravity. Competitive window: exodus of free-tier users looking for a terminal agent → directly relevant to Unown.
- **Docs moved to https://geminicli.com** (Astro/Starlight). The in-repo `docs/` folder now holds only a subset (`docs/index.md`, `docs/cli/cli-reference.md`, `docs/cli/headless.md`, `docs/cli/sandbox.md`, `docs/cli/settings.md`, `docs/cli/checkpointing.md`, `docs/reference/commands.md`, `docs/tools/mcp-server.md`, `docs/hooks/`, `docs/extensions/`, `docs/cli/tutorials/`). **`docs/cli-ui.md` is gone (404)** — UI docs now live in `docs/reference/keyboard-shortcuts` on the site. Verified by probing raw.githubusercontent paths.
- Old features from earlier 2025 docs that are **gone today**: `/profile` (GEMINI.md profiles), `/statsig`, `/sync`, `--check-legacy` sandbox check, `--checkpointing` CLI flag (removed in v0.11.0; settings-only now), `--allowed-tools` (deprecated → Policy Engine), `-y/--yolo` (deprecated → `--approval-mode=yolo`). Do NOT port these as "current".
- Headless exit codes are **0 / 1 / 42 (input error) / 53 (turn limit)** — a different contract from Unown's 0/1/2/3/4.

## Top gaps

Ranked by value to Unown's **existing** feature set (workflow rationale, implementation sketch, effort S/M/L).

1. **Interactive session browser + resume picker** (MISSING, effort **M**)
   - Rationale: Unown's `--resume <id|name|path>` requires knowing the ID; Gemini's `/resume` browser (search with `/`, sort by date/count, preview first prompt, `x` to delete, Enter to resume) plus `--list-sessions`/`--delete-session` is the single biggest daily-workflow gap. Unown already has `unown sessions list` data and a mature TUI list-widget layer (used by `/addons`, `/providers`, dashboard) — this is assembling known parts.
   - Sketch: add `/resume` (bare) → TUI list over the sessions store: columns [date, turns, title, id]; `/` fuzzy filter (reuse repomap/palette fuzzy code); Enter → load; `x` → delete with confirm; wire `unown --list-sessions` and `unown --delete-session <n>` as thin aliases over the same store. Keep `/resume <id|name|path>` as-is.

2. **Context compression: `/compress` + auto-threshold** (MISSING, effort **M**)
   - Rationale: Unown's headless `-p` and long TUI sessions die at context walls; Unown is a self-improving agent that already runs long multi-turn dream/review loops. Gemini triggers auto-summarization at `model.compressionThreshold` (0.5) using dedicated cheap "compression model" aliases and offers manual `/compress`.
   - Sketch: summary turn: on threshold, call the current provider (or the cheapest configured model) with a "summarize conversation so far, keep open todos/goals/decisions" prompt; replace history except system+memory injections; surface a `[compressed]` marker + `/context` stat. Add `unown -p --compress-at 0.5`. Fits Unown's engine (the detached engine can own the summarizer).

3. **Headless `stream-json` output** (MISSING, effort **S–M**)
   - Rationale: Unown's exit contract (0/1/2/3/4) and JSON envelope match Gemini's `--output-format json`; CI users of every agent CLI are converging on NDJSON event streams (`init/message/tool_use/tool_result/result`) — e.g. Gemini, Claude Code, Codex. This makes Unown scriptable/observable mid-run (progress bars, tool auditing) without changing the existing envelope.
   - Sketch: extend `-p` with `--output-format stream-json`: emit `{"type":"init",...}` on start, per-turn/per-tool events the TUI already renders, and a final `result` object identical to today's envelope. No exit-code changes.

4. **Declarative TOML policy engine layered on existing permissions** (INCOMPLETE, effort **L**)
   - Rationale: Unown already has allow/deny/ask + trust gating and a hooks gate system; Gemini's Policy Engine shows the evolved end-state: `[[rule]]` TOML with `toolName` wildcards, `argsPattern` regex, `commandPrefix`, priority numbers, per-approval-mode and per-subagent scoping, admin tier, and "deny hides the tool from the model entirely" (saves context). Unown's `unown recipes` already parses TOML-ish bundles, so the parsing machinery exists culturally.
   - Sketch: `.unown/policies/*.toml` evaluated inside the existing permission gate (same allow/deny/ask enum); priority = file order + `priority` field; wire `ask` to the existing ask dialog; `/permissions` gains a `rules` view. Ship with 2–3 starter rules (deny `.env` writes, ask on `git push`).

5. **OS-level sandboxing profiles** (MISSING, effort **L**)
   - Rationale: Unown ships `--permission-mode bypassPermissions`; without OS isolation that flag is a footgun. Gemini offers Docker/Podman (default image `ghcr.io/google/gemini-cli`), Seatbelt profiles, custom `.gemini/sandbox.Dockerfile` w/ auto-build (`BUILD_SANDBOX=1`), tool-level sandboxing (`security.toolSandboxing`), and sandbox-expansion prompts when a command needs more access.
   - Sketch (pragmatic subset): `--sandbox docker` → run bash tool through `docker run -v $PWD:$PWD -w $PWD` (+ `--network none` by default); allow-list extra paths via settings; expansion prompt when a command fails on EACCES/network. Tool-level only (bash + file tools), not whole-process — same choice Gemini made with `security.toolSandboxing`.

6. **Terminal notifications** (MISSING, effort **S**)
   - Rationale: Unown's async fleet, long `-p` runs, and blocking `ask_user_question` all create "wait then come back" workflows; Gemini emits OSC 9 notifications (action-required, session-complete) with BEL fallback — ~50 lines of escape-sequence code for a big perceived-polish win.
   - Sketch: settings `general.notifications` (default off? Gemini defaults off too); emit `ESC ] 9 ; "Unown: needs approval" BEL` on ask/permission prompts and on turn completion; detect OSC-9 support the same way (iTerm2/WezTerm/Ghostty/Kitty), else `\a`.

7. **Session retention + `--delete-session`** (MISSING, effort **S**)
   - Rationale: Unown sessions + receipts + blame ledger accumulate forever; Gemini auto-prunes (`sessionRetention.enabled/maxAge "30d"/maxCount/minRetention "1d"`) and deletes associated artifacts with the session. Pairs with existing `unown sessions` commands; cheap, and `unown doctor` can report on it.
   - Sketch: settings `sessions.retention.maxAge/maxCount`; prune on engine start; `unown sessions delete <id>` + confirm; keep receipts/blame rows (audit) but drop blobs.

8. **`@file:line` mentions + configurable filtering** (INCOMPLETE, effort **S**)
   - Rationale: Unown's pi TUI already does `@file`; Gemini (v0.64, Oct 13 2026) added `@file:line` resolution and exposes git-ignore-aware filtering knobs (`respectGitIgnore`, `respectGeminiIgnore`, `enableFuzzySearch`). Deep-linking to a line + respect `.unownignore` makes @ mentions precise and cheap.
   - Sketch: extend pi's `@` completer: `file.ts:123` → read_file with start/end lines; add `.unownignore` (gitignore syntax) honored by @ and grep tools; done.

9. **Unified `/rewind` picker over existing undo primitives** (INCOMPLETE, effort **M**)
   - Rationale: Unown has checkpoint/undo/redo/restore/edit-resend but they're separate commands; Gemini's `/rewind` (Esc Esc) shows every past interaction with a preview and one dialog: rewind conversation / revert code / both. This is UX glue over machinery Unown already owns (receipts ledger even has per-turn file-touch data via `unown blame`).
   - Sketch: `/rewind` opens list of user turns (from session log); selecting turn N offers [history only / files only / both]; files-only uses existing checkpoint restore keyed to that turn; history-only truncates the transcript (Unown already persists sessions as append-only logs).

10. **Trusted-folder discovery scan** (INCOMPLETE, effort **M**)
    - Rationale: Unown is trust-gated, but trust today is binary. Gemini's folder-trust dialog runs a **discovery scan** first: lists every project-loaded command/MCP server/hook/skill/setting-override with security warnings before you grant trust, and untrusted folders run in safe mode (no workspace settings, no .env, no MCP, no custom commands, no auto-accept). This protects Unown's self-learning layer, which loads *more* project config than most agents (recipes, watch.json, agents, hooks).
    - Sketch: on first run in a dir, scan `.unown/` for commands/hooks/agents/mcp/settings/recipes/watch; show them in the existing TUI select-list; trust choice stored in `~/.unown/trusted.json`; untrusted = ignore all project config + force default permission mode. `unown doctor-instructions` already audits most of these — reuse its scanner.

Honorable mentions (worth a backlog row each): MCP OAuth discovery (`/mcp auth`), remote A2A subagents, `.agents/skills` interop alias, installable extension bundles + gallery, `/setup-github`, `GEMINI_SYSTEM_MD`-style system-prompt replacement, per-tool output token budgets (`model.summarizeToolOutput`), `/copy` OSC 52, session recording (F6/F7), voice mode, model steering hints for the *main* agent (Unown has it for fleet children only), `/settings` editor dialog with published JSON schema, `/quit --delete`, `/bug`, enterprise system-override settings file, update_topic narration, task-tracker DAG with `tracker_visualize`.
