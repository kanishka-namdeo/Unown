## THE GENUINE GAP (the §5 reflection, the round's most instructive
failure)

**Root cause (operator-diagnosed, A2-fixed):**
`createIdbStorage` passed the upgrade handler as a THIRD argument to
`factory.open(name, version, callback)` — the real
`indexedDB.open(name, version)` takes TWO; the extra arg is silently
ignored, `req.onupgradeneeded` stays null, the version-change upgrade
runs with no listener, **no object stores are ever created**, and the
first `transaction([STORE_META, STORE_DATA])` throws NotFoundError →
the app boots to the empty state (0 rows offline reload).

**Why only e2e could catch it:** the unit lane runs on FakeStorage by
design (PLAN §6: "no real IDB ever appears in the unit lane") — the
adapter's REAL-API conformance is untestable there. **PLAN Appendix B
risk #2 fired exactly as pre-registered** ("IDB schema-migration loss
under real quota pressure… the L-11 e2e runs migrations on real
Chromium IDB — the only lane that touches real IDB").

**The fix (the right layer):** the two-arg `open` signature in
`IDBFactoryLike` + the handler attached to `req.onupgradeneeded`;
every other behavior identical. The debug temp spec deleted (never
landed). Before/after: 0 rows → the seeded row renders offline; e2e
red → 2/2 green in 1.6 s.
