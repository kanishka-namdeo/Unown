## The §5 reflection — the pins dual-laned (AFTER: GREEN)

The `assertMemories` precedent applied to all three (live lane +
fixture lane, never a widening to nothing):

- `assertOverview`: `version` accepts string (fixture) OR object with
  `version.version: string` (live).
- `assertNotes`: id raw-passthrough (number-or-string); the content
  lane `text` (fixture) OR `content` (live); the timestamp lane `at`
  OR `created_at` (string-or-number — the live wire sends epoch ints);
  the optional provenance fields null-tolerant (the live wire NULLS
  absent optionals explicitly).
- `assertSpend`: the live lane pins `now/routines[]/total{day,week,cap,
  throttledNow,drainAt}` (per-routine windows included); the fixture
  lane keeps the six canned fields verbatim.
- **`mapNotes`** went raw-passthrough (the old `Number(n.id)` coercion
  silently replaced every live uuid with a row index — V-24 fiction #1
  in the mapper), bridging `content`/`created_at`.
- **`mapSpend`** (new) maps the live body honestly (`calls` =
  `total.day.runs`, `windowLimit` = `total.cap` — both sides spell
  "0 = unlimited" — `throttled` = `throttledNow`) and carries the
  native windows in `SpendReport.live`; `renderSpendMeter` renders the
  live windows when present (the fixture-lane rendering verbatim
  otherwise) — the spend panel is ALIVE against the real engine again,
  and `data-live-wire` marks the live lane in the DOM.
- The live-wire pins for all three: hand-committed verbatim bodies +
  drift mutations in `live-wire.test.ts` (e/f/g/g2) — the pins are
  pinned by more than the regenerable recording.
