One surgical fix, precisely diagnosed. The 390px mobile covenant still
fails by 42px (scrollWidth 432) and the culprit is EXACTLY ONE element:
the sr-only axis data table in src/components/encore/views/baseline.tsx
(<table className="sr-only"><caption>The seven VLM axis means from the
baseline receipt</caption>...).

Diagnosis (verified by computed-style probe): Tailwind v4's .sr-only sets
width: 1px, but the scoped globals.css styles tables with a HIGHER-
specificity selector that overrides the width on table elements — the
table re-expands to its natural 392px layout width inside the padded
container (left: 40, right: 432) even though it is position: absolute and
visually clipped. The class works on DIVs because divs carry no table
width semantics.

The fix: wrap the table in a <div className="sr-only"> and remove the
class from the <table> itself (the div gets the 1px clip; the table inside
inherits the hidden context with zero layout footprint). Keep the table's
caption/semantics EXACTLY as they are — screen readers lose nothing.
