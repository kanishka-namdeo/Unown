## The O-1 root cause (the round's best §5-class find, fixed in-lane)

The C-5 PRECACHE_LIST carried the sub-modules as `.ts` URLs, but the
transpiled `app.ts`'s import specifiers keep the `./x.js` convention —
the browser's module graph requests the `.js` forms. On the offline
reload, `cache.match("src/domain/types.js")` MISSED (the install
precache held the `.ts` key; the runtime belt was empty — the first
load's sub-resources were fetched pre-`clients.claim()`), fell through
to offline.html, and served HTML for a JS module → the parse failed →
the shell stalled on "Booting…". **Fix at the SW layer**: the
PRECACHE_LIST keys are the `.js`-convention URLs the browser actually
requests (the Ostinato O-4 offline-boot law — install keys must match
the module-graph requests); `src/ui/app.ts` stays the `.ts` URL
index.html requests. The O-1 lane now boots the full surface offline.
