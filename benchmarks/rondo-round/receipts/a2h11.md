  aggregation > per-routine + global windowed sums (24h + 7d), the boundary,

## Root-cause chain (operator-proven by live repro)

1. The `automations` SQLite table is created **only** by
   `ensureAutomationsSchema()` (`src/automations.ts:456`, exported) — called at
   engine boot and lazily by mutators such as `createAutomation()`. It is
   **never created at module scope**.
2. The test file's `beforeAll` (`test/automation-spend.test.ts`, ~line 108)
   runs `store.run('DELETE FROM automations')` directly, without first
   ensuring the table exists.
3. That DELETE therefore **silently depends on some OTHER test file having
   run a mutator first** (which lazily created the table in the shared
   SQLite db).
4. Bun's test-file order **varies by platform**. On Linux/macOS in the full
   suite, an earlier file happens to create the table first → green. On
   Windows CI (and on Linux in isolation), no prior mutator ran → the table
   is absent → `no such table: automations`.

So: order-dependent test isolation. The defect is entirely in the test
file; `src/` and the schema are correct.

## The fix (one surgical change, one file)

`pi-repo/packages/self-learning/test/automation-spend.test.ts`

- Add `ensureAutomationsSchema` to the existing import from
  `../src/automations.ts`.
- Call it as the **first statement** of the `beforeAll` (before both
  `DELETE FROM` statements), with an explanatory comment.

Exact diff:

```diff
 import {
         AutomationsScheduler,
         createAutomation,
+        ensureAutomationsSchema,
         getAutomation,
         listRuns,
         updateAutomation,
         type AutomationRow,
 } from "../src/automations.ts";

 describe("automation spend aggregation", () => {
         beforeAll(() => {
-                // Test isolation: failed runs in earlier suites leave rows behind
+                // Test isolation: the automations table is only created by
+                // ensureAutomationsSchema() (engine boot / mutators) — never at
+                // module scope. Ensure it here so this file is green in
+                // isolation on any platform (no dependence on an earlier test
+                // file having run a mutator).
+                ensureAutomationsSchema();
+                // Failed runs in earlier suites leave rows behind
                 // (their inline drop() never ran) — start from a clean slate.
                 store.run(`DELETE FROM automations`);
                 store.run(`DELETE FROM automation_runs`);
```

No `src/` file, no other test, no assertion, and no schema was touched.
