# The Planning Gap Register (benchmarks/plan-mode/)

The Plan Mode V2 round's governing artefact. Every gap follows the round's loop:
**reproduce → classify root cause → create benchmark → create regression test → implement planner improvement → validate improvement → re-run original task.**

Research base: the 2026-10-31 competitor sweep (Claude Code, Gemini CLI, Roo Code, OpenHands/OpenDevin, Cline, Codex CLI, Aider — sources in `docs/plan-mode-competitor-research.md` and the round session log) plus the live baseline reproductions below (receipts: `results/baseline/`).

Scoring: every plan is scored by the deterministic rubric in `score-plan.mjs` (0–100; dimensions: objective, context, approach, steps, risks, verification, clarity — the same scorer the product's `plan_write` tool returns, single source of truth in `pi-repo/packages/self-learning/src/plan.ts`).

## Non-goals (recorded, deliberately not gaps)

- **Permission-mode `plan`** (a 4th `PermissionMode` in the permission engine): Unown's plan mode is an extension-level state machine with its own tool gating; duplicating it into the permission engine adds a second source of truth for the same restriction. The approval options DO map to permission-mode transitions (acceptEdits/default) — that is where the two systems meet.
- **Headless auto-approval** (`--plan-execute`): the approval gate is the safety property of plan mode; an unattended plan→execute pipeline is the standing-orders/`--goal` lane, not plan mode. Print mode stays read-only and reports the plan in the JSON envelope.
- **Plan DAG / dependencies** (Gemini's experimental `tracker_*`): the flat ordered-step model matches what terminal agents actually execute; dependencies arrive via the todo tool when the model wants them. Revisit when the todo tool grows a dependency UI.
- **`/plans` archive browser**: `.unown/plans/` is a plain directory of markdown files — `ls` + `$EDITOR` is the archive. A picker command is trivial follow-up if users ask.

## Re-run protocol

After every planner improvement: re-run the fixed task set (`tasks/`) under the same cap/model/endpoint, score with the SAME scorer, commit per-run JSONL receipts, and update `RESULTS.md`. The suite is the regression net for every future plan-mode change.
