## [Unreleased]

### Added

- **Landing page: quickstart carries the SDLC-parity session surface** — the quickstart's command list gains the `unown --goal "…"` line ("durable goal — completion needs cited evidence") and its session-tools paragraph now names the 2026-10-18 feature-parity additions: `lsp` ("language-server intelligence — diagnostics ride every edit"), the MCP join story (`.unown/mcp.json` → `mcp__server__tool`), and the six load-bearing slash commands (`/plan /review /goal /undo /receipts /mcp`). Text-only change on the existing grid and classes — palette gate re-run PASS (21 dark + 21 light tokens, all AA), quickstart component test extended to pin every new claim (changed-line coverage stays satisfied), production build verified; the full both-scheme contrast + theme-toggle + axe audits run in the CI e2e gate as on every push. Copy rationale recorded in `docs/landing-research.md` (one-fact-per-section respected: no other landing section states any of these).
- **Agent Behavior: `/review` — parallel-subagent code review** — `/review [base]` (TUI) freezes a diff snapshot (uncommitted work: diff vs HEAD + untracked files; or a base branch's merge-base range; 40 k-char cap) and sends read-only reviewer subagents over it: one for small diffs (< 6 k chars), three in parallel with split focuses (correctness · security · tests/maintainability) for larger ones — the oh-my-pi reviewer-count heuristic. Reviewers follow a strict output contract (`[P0]…[P3]` findings with confidence + file:line citations, `VERDICT: SHIP|DO-NOT-SHIP`); `parseReviewOutput` extracts them tolerantly, `mergeReviews` dedupes by normalized title (most-severe wins) and takes the strictest verdict; the rendered review notifies and lands in `.unown/reviews/` (gitignored). Reverse-engineered per [docs/sdlc-feature-parity.md](docs/sdlc-feature-parity.md) (oh-my-pi `/review` + Codex `/review` presets). Honest limit, stated in docs: severity/confidence are the reviewing model's judgment, not verified facts. Pinned by `test/review.test.ts` (11 tests: parsing, merging/dedupe/strictest-verdict, rendering, artifact persistence, `captureReviewTarget` against throwaway git repos in both modes, reviewer config + task prompt).
- **Agent Behavior: `/goal` + `--goal` — durable, evidence-verified objectives** — the zcode Goal Mode + muse goals port. `/goal <objective>` (TUI) or `unown --goal "<objective>"` (print/TUI) sets a goal persisted as a session entry (survives `/new` `/resume` `/fork`); while active, every turn carries the objective plus the completion contract (`[GOAL:COMPLETE]` tag + cited evidence + unfinished todos block completion — `goalContextMessage`); the completion gate (`checkGoalCompletion` in `goal.ts`, wired to `agent_end`) requires the tag, every session todo done, and ≥2 distinct evidence markers (file paths and/or command output — a line can count for both), then marks the goal complete and records the evidence, or reports exactly why it failed. `/goal` status, `/goal pause|resume|clear`; the context filter keeps only the newest goal-context message (stale injections never accumulate). Honest limit, stated in docs: the gate verifies that evidence was *cited*, not that it is true. Pinned by `test/goal.test.ts` (14 tests: command parsing, context contract, completion-gate accept/reject paths, status rendering, path resolution, and the full extension wiring through a fake pi — set/inject/accept, reject-with-warning, pause/resume/clear, `--goal` flag bootstrap, session-entry restore); live receipt: a headless `--goal` session that created `sum.ts`, cited the file, and closed with `[GOAL:COMPLETE]` accepted by the gate.
- **Agent Behavior: MCP client (`mcp__<server>__<tool>` tools + `/mcp`)** — unown is now an MCP client. Servers configured in `.unown/mcp.json` (project) or `~/.unown/agent/mcp.json` (user; project wins per server name) in the Claude-Code-compatible `mcpServers` shape: stdio entries (`command`/`args`/`env`/`cwd`) and streamable-HTTP entries (`url`/`headers`), `${VAR}` expanded from the environment. Stdio speaks newline-delimited JSON-RPC with a pretty-print-tolerant depth-aware parser; HTTP POSTs with `Mcp-Session-Id` capture/replay and parses both `application/json` and `text/event-stream` responses; Windows spawns through `cmd.exe` so `npx`/`.cmd` shims resolve. Connections are lazy and never block the session (background connect at session_start; a failed server marks `error` with its stderr tail and stays out of the way — zcode's rule); tools register dynamically via `pi.registerTool` as `mcp__<server>__<tool>` (sanitized, 100/server cap, 500-char description cap, 16 k-char result cap). `/mcp` reports status and reconnects. Env: `UNOWN_MCP=0` or `disabled: true` disables; `UNOWN_MCP_TIMEOUT_MS` (120 s), `UNOWN_MCP_CONNECT_TIMEOUT_MS` (20 s). Reverse-engineered per [docs/sdlc-feature-parity.md](docs/sdlc-feature-parity.md). Pinned by `test/mcp.test.ts` (23 tests: config layering + env expansion, naming/schema/description helpers, SSE parsing, spawn-spec, the accumulator (NDJSON + pretty + chunk splits + brace-in-string), live stdio protocol against `test/fixtures/mock-mcp-server.mjs` (flat + cursor-paginated lists, error tools, pretty mode, missing-binary degradation), live streamable HTTP against an in-process `Bun.serve` mock (JSON + SSE modes, session-id replay), and the extension factory through a fake pi (dynamic registration, disabled flag, failed-server resilience)); live receipt: a headless session where the model called the dynamically-registered `mcp__mock__echo` tool and got `echo: mcp works` back.

## [2.1.0] - 2026-10-18

### Added

- **Agent Behavior: session checkpoints + receipts audit ledger (`/checkpoint` `/undo` `/restore` `/checkpoints` `/receipts`)** — every terminal session now records what it did and can take it back. A receipts ledger (`.unown/receipts/<session>.jsonl`, one per session boot, subagents marked `[subagent]`) captures the ordered audit: session starts, prompts (first 200 chars), every tool call with bounded input (4 KB cap), every result (ok/fail + usage), checkpoints and restores — `/receipts [n]` renders the last n with totals. A checkpoint store (`.unown/checkpoints/`, content-addressed blobs + manifests) seals a **turn checkpoint** automatically whenever a turn wrote files — the *pre-turn* state of every changed file (new files tombstoned) — and `/undo [n]` reverts the last n turns (restores before-images, deletes tombstoned files, consumes walked-back checkpoints). `/checkpoint [label]` snapshots the current state of every session-touched file; `/restore <id|label>` rewrites it (prefix matching). Both trees are gitignored; restore is jailed to the project dir; ≤40 manifests kept with blob GC; ledger capped at 5000 entries. Reverse-engineered from codewhale's receipts surface per [docs/sdlc-feature-parity.md](docs/sdlc-feature-parity.md). Known limits (stated in docs): bash-caused changes are ledger-recorded as commands but not itemized per-file; `/undo` walks only the current process's turns — cross-process via `/checkpoint`+`/restore`. Pinned by `test/checkpoints.test.ts` (19 tests: jail/slug/preview helpers, ledger round-trip + truncated tail + cap, store blobs/tombstones/restore outcomes/prune-GC, and the full turn lifecycle through a fake pi including failed-write drop and subagent marking); live receipt: a headless session whose write landed in the ledger (tool_call+tool_result+checkpoint entries) with the sealed turn checkpoint on disk (`docs/sdlc-feature-parity.md`).
- **Agent Behavior: LSP code intelligence (`lsp` tool + `/lsp` + PostToolUse diagnostics loop)** — every terminal session now registers an `lsp` tool (actions: `status`, `diagnostics` per file or `all`, `hover`, `definition`, `references`, `symbols`) speaking real LSP over stdio JSON-RPC (`pi-repo/packages/self-learning/src/lsp.ts`, zero deps, pure TS, Windows-safe). Language servers are auto-detected on PATH (typescript-language-server, pyright/basedpyright/pylsp, gopls, rust-analyzer, clangd, bash-language-server, ruby-lsp, intelephense) with config overrides from `~/.unown/agent/lsp.json` and `.unown/lsp.json` (project wins; `disabled: true` or `UNOWN_LSP=0` kill the whole surface). After every `write`/`edit` the fresh diagnostics for that file are appended to the tool result and error-severity findings mark it `isError` — the agent gets compiler feedback instead of compounding broken edits (mirrors the Bun syntax gate; cold start never blocks a tool result — the first edit warms the server, the second onward gets feedback; `UNOWN_LSP_WAIT_MS` default 10 s, `UNOWN_LSP_TIMEOUT_MS` default 15 s). Reverse-engineered from oh-my-pi's `lsp` tool per [docs/sdlc-feature-parity.md](docs/sdlc-feature-parity.md). Plan mode keeps `lsp` active (read-only). Pinned by `test/lsp.test.ts` (38 tests: pure helpers, registry/config precedence, and live protocol tests against `test/fixtures/mock-lsp-server.mjs`); live receipts: agent session calling `lsp diagnostics` on a flagged file, and a `write` whose result carried the diagnostic back (`docs/sdlc-feature-parity.md`).
- **docs: `sdlc-feature-parity.md`** — decision record for the 2026-10-18 feature-parity effort: what oh-my-pi, zcode, muse code, codewhale and the other 2026 agents ship, what Unown adopts (LSP, checkpoints/receipts, MCP, `/review`, `/goal`), what is already present, and why the rest stay out — every port re-derived against pi's documented seams per the standing swap-assessment invariant.
- **Self-update: `unown update`** — the update lifecycle for installed agents (design researched against Claude Code `claude update`, ohmyzsh `omz update`, Codex/Gemini update-notifier, rustup, brew). `unown update` fast-forwards the git-checkout install to the newest *ready* release tag (`git fetch --tags` + `git merge --ff-only`), re-runs the installer (deps, engine build, `.env`-preserving bootstrap, PATH shim), verifies the version actually moved (anti-shadowing), and **auto-rolls-back to the recorded pre-update commit when the rebuild fails**. Guards, each refusing with actionable guidance: dirty tree (opt in with `--allow-dirty` = git `merge --autostash`), pinned/detached installs without an explicit version, local commits ahead of the remote, non-descendant targets. A half-pushed tag (its `package.json` disagreeing with the tag name) is never offered. `unown update <version>` pins/rolls back explicitly; `unown update --rollback` restores the recorded state; `unown update --check` is non-mutating (exit `0` up to date, `2` available, `1` error) with a `--json` variant for scripts. State (`~/.unown/update-check.json`, `update-state.json`) lives outside the repo — the updater never dirties the user's tree.
- **`unown uninstall`** — the reverse of the install path (rustup `self uninstall` pattern): removes only the PATH shims that point into THIS checkout (foreign shims reported, never touched), keeps `~/.unown` memories by default (`--purge-data`) and the checkout (`--purge-checkout`, which refuses uncommitted work), `--dry-run` supported.
- **`unown doctor --json`** — machine-readable diagnostics (`{ok, version, checks[{id,status,detail}], summary}`) with unchanged exit semantics; scriptable and CI-able. Doctor also reports the version + short SHA + checkout path, the cached update-check state, and the user-state schema version.
- **`unown info`** — the bug-report support bundle: version, platform/toolchain, git state, provider names (baseUrls credential-redacted; `auth.json` existence + file mode only, contents never read), update-check state, active opt-outs. Human + `--json`; paste-safe by construction.
- **`unown completions bash|zsh|fish|powershell`** — static ASCII completion scripts; a drift test pins every script to mention every CLI command word.
- **User-state migrations** — forward-only `~/.unown` schema migration runner (`~/.unown/migrations.json`, capped history, non-fatal failures, downgrades never walk back). Zero migrations exist at v1; the mechanism ships so the first real one has somewhere to land. Runs after `unown update` applies; reported by doctor.
- **Supply-chain hardening (OpenSSF Scorecard quick wins)** — every `uses:` across all workflows pinned by full commit SHA (peeled-commit SHAs, version noted in a trailing comment); `ci.yml` gains a least-privilege `permissions: contents: read` block; `bash -n` covers `public/*.sh`; new `.github/dependabot.yml` (weekly github-actions + bun updates — `bun.lock` natively supported — and monthly pi-repo sync candidates, majors ignored by default), `.github/workflows/codeql.yml` (SAST: weekly + push/PR, `build-mode: none`, noisy generated/vendored trees excluded via `.github/codeql-config.yml`), and `.github/workflows/scorecard.yml` (weekly OpenSSF Scorecard, `publish_results: true`, harden-runner audit mode) plus the README scorecard badge. Remaining long-term Scorecard items documented as accepted: Signed-Releases (artifact signatures), Fuzzing (OSS-Fuzz), Packaging (registry). Branch protection on `main` is a repo-settings action left to the owner (not expressible in files).
- **One-line installer** — `curl -fsSL https://unown-nine.vercel.app/install.sh | sh` (`public/install.sh`, served by the site deployment): refuses root, checks git, bootstraps bun via bun's own installer when missing, clones (main, or `--version vX.Y.Z` pinned), runs the repo installer; whole body in a `main(){…}; main "$@"` wrapper with `set -eu` (the standard curl-pipe-sh mitigations); review-first and checksum.sh documented. Release workflow now attaches `sha256sums.txt` to every GitHub Release. New doc: [docs/install.md](docs/install.md) (one-liner, manual, requirements, offline/air-gapped, uninstalling).
- **Update notifications** — interactive sessions show a one-line "update available" notice: TTY-gated, CI-suppressed, 24h-cached, refreshed by a detached background child running a read-only `git ls-remote` (no GitHub API, no rate limit, works with private/self-hosted remotes; never blocks startup). `unown doctor` now reports the version, short SHA, checkout path and last check state. Opt-outs: `NO_UPDATE_NOTIFIER` / `UNOWN_DISABLE_AUTOUPDATE` / `DO_NOT_TRACK` (background check only) and `UNOWN_DISABLE_UPDATES` (all update paths — the org/CI kill switch). Remote URLs are credential-redacted before any output or state write (a PAT embedded in the git remote never leaks — unit-pinned).
- **`unown changelog [n]`** — prints the latest `CHANGELOG.md` sections; a successful update prints the changelog slice for the crossed versions plus the release-notes URL.
- New user-facing doc: [docs/updating.md](docs/updating.md) — the full update contract (commands, exit codes, guards, pinned installs, rollback, offline/air-gapped use, privacy). Tests: `pi-repo/packages/self-learning/test/update.test.ts` (39 tests — semver, ls-remote parsing, notice gating, and the whole cmdUpdate flow against throwaway local git repos, including the PAT-redaction leak guard).
- **DOX (agent workflow)** — root `AGENTS.md` gains a **Git Preflight** section: every task opens, and the Closeout commit is preceded, by `git fetch` → measure `HEAD...@{u}` → `git pull --ff-only` (never a bare `git pull`, which is fetch + merge and can merge uninvited). A dirty tree is worked around, never cleared by `stash`/`restore`/`clean`/`reset --hard`; a diverged branch stops for the user's choice instead of an agent-side merge or rebase; and a moved tree refreshes what changed (`bun install`, `db:push`, service restart) and re-reads the AGENTS.md chain, because DOX is code. `CONTRIBUTING.md` points at it. This is a repo-workflow rule, not a runtime change — no prompt, model, routing, guard or hook moved, so [docs/BEHAVIOR.md](docs/BEHAVIOR.md) is unchanged.
- README: bespoke four-tier memory-stack diagram (`.github/assets/diagram-memory.png`, GBA brand palette, regenerable from `scripts/brand/diagram-memory.html`, layout-gated by `scripts/check_overflow.mjs`); README restructured 34 KB → 24.5 KB with every moved section landing in `docs/` (integrity gates + session walkthrough → `docs/memory.md`, production notes → `docs/configuration.md`, repository layout → `CONTRIBUTING.md`).
