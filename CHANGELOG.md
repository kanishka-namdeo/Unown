### Added (Agent Behavior)

- **local model lane for background learning** — the llm-bridge gains an optional SECOND upstream (`BRIDGE_LOCAL_URL`/`BRIDGE_LOCAL_KEY`/`BRIDGE_LOCAL_MODELS`): any local OpenAI-compatible server (llama.cpp `llama-server`, Ollama, LM Studio). Model ids matching `BRIDGE_LOCAL_MODELS` — or any `local-*` id when the list is empty — are forwarded there instead of the remote upstream: keyless by default, no spacing throttle, and the resolved qwen `enable_thinking` is mirrored into llama.cpp's `chat_template_kwargs` dialect (family detection strips a leading `local-`, so `local-qwen3-0.6b` gets the same thinking-off default; a `local-*` id with no local server degrades onto the remote allow-list rather than hard-failing). The learning layer can pin individual subtasks to the lane — `PI_MINER_MODEL_ID` (failure mining), `PI_DREAM_MODEL_ID` (AutoDream), `PI_SKILLS_MODEL_ID`, `PI_MINT_MODEL_ID` (task minting) — via a new `model` option on `llm.ts chat()/chatJson()`; unset = the all-remote topology, byte-identical. Agent sessions are deliberately NOT routable this way: the evaluation scoped the lane to auxiliary work. `/health` reports the lane (`local {ok,url,models}`), `/v1/models` advertises its ids, and the request log tags local-routed calls as `local:<id>`. One-liner lane: `node benchmarks/local-llm/runner.mjs serve --model qwen3-0.6b` (downloads llama.cpp b11718 + GGUF per platform). Verification: bridge suite 106/106 (routing goldens + thinking-compat + loadConfig local fields); engine suite 970/970; E6 — the production `mineFailure()` over the lane returned a harness-accepted MiningResult in 99.8s whose patch lines matched the insight the engine itself shipped for the same task. Basis: [benchmarks/local-llm/results/REPORT.md](benchmarks/local-llm/results/REPORT.md) — verified hypotheses H1–H4 (triage/mining/dream quality parity at $0, blind A/B judge ties on 4/4 real failed runs, 100% harness-validator pass vs the remote's 50%), H5 refuted (minting stays remote), H6 cross-platform (CI probe green on ubuntu/macos/windows; lane-by-RAM guidance; measured KV-q8_0 4.4× CPU-prefill trap).

- **Hardening (integrity): checkpoint store** — blob and manifest writes are atomic (temp + fsync + rename via the package's `atomicWriteFileSync`), a truncated blob parked at a content-addressed path self-heals on the next write, and every restore now verifies `sha256(blob) === manifest.hash` (mismatch → `corrupt-blob`, never silently wrong content). Restore is jailed by both the lexical project-root check AND a realpath check — an in-project symlink whose target escapes the project is refused (capture follows symlinks; restore writes never do). Blob GC keeps a 10-minute grace window and never deletes blobs newer than the newest surviving manifest, so a concurrent session's put→seal window can no longer have its blobs deleted by another session's prune (the audit's reproduced race). Files larger than `UNOWN_CHECKPOINT_MAX_BLOB_BYTES` (default 64 MiB) are not blobbed — the turn still reverts its other files and the ledger notes the exception once. Pinned by `test/checkpoints.test.ts` (19 → 37).
- **Hardening (transport): LSP client** — a dead language-server no longer kills the diagnostics loop for the rest of the session: the connection is evicted, that server's open-document state is cleared (the next edit re-`didOpen`s on a fresh process), crashes are counted and surfaced in `status()`, restarts are gated (30 s cooldown via `UNOWN_LSP_CRASH_COOLDOWN_MS`, max 3 per server per session — then syncs skip cheaply instead of spawning in a loop), and pending requests reject instead of hanging. Message framing is bounded: `Content-Length` is capped (`UNOWN_LSP_MAX_MSG_BYTES`, default 32 MiB — violations recycle the connection rather than buffering), LF-only headers are tolerated, and garbage before a valid frame is skipped. `waitForFreshDiagnostics` bails when the connection dies mid-wait and skips servers that have never published (the PostToolUse loop no longer burns its full wait budget on such files). Pinned by `test/lsp.test.ts` (38 → 47).
- **Hardening (transport): MCP client** — the stdio accumulator can no longer be poisoned: depth is clamped ≥ 0 (a stray `}`/`]` used to silence every subsequent message), garbage/NUL/binary junk is isolated and skipped without eating the next message, and messages are capped (1 MiB per message / 4 MiB buffer, surfaced as an error with stream recovery). HTTP transport recovers: a 404 re-initializes once with a new session id and replays; 429/503 backs off honoring `Retry-After` (≤ 2 retries); aborts are rewritten as clear timeout errors; notifications are bounded (10 s AbortController). Lifecycle: the background connect and every registration path are guarded (no unhandled rejection can kill the session), a failed/dead server cools down before reconnecting (`UNOWN_MCP_RECONNECT_COOLDOWN_MS`, 30 s — `/mcp` force-throughs), a ping keepalive marks dead servers errored (`UNOWN_MCP_PING_INTERVAL_MS`, 60 s), reconnects dispose the old connection first, and tool registration is session-scoped (a second session runtime in the same process gets its `mcp__*` tools again — previously zero). Pinned by `test/mcp.test.ts` (23 → 43, new fault mode `MOCK_MCP_GARBAGE=1`).
- **Hardening (lifecycle): child reaper** — new `src/child-reaper.ts`: a process-wide registry of live LSP/MCP server children; `installChildReaper()` (idempotent, installed at CLI boot) hooks `process.once("exit")` + SIGINT/SIGTERM and kills every registered child synchronously (SIGTERM→SIGKILL) — a Ctrl-C or abrupt death of the agent no longer orphans `npx` wrappers and server processes. Pinned by `test/child-reaper.test.ts` (5).
- **Env knobs** — all LSP/MCP/checkpoint ms/byte env vars parse tolerantly (NaN/negative/zero/absurd → default) through one shared `parseMsEnv`; new vars documented in `docs/configuration.md` and `.env.example` (which also back-fills the previously missing `UNOWN_LSP*`/`UNOWN_MCP*` entries).

### Agent Behavior

- **`/undo` is session-scoped by default (`--all` for the rest)** — turn checkpoints carry an `owner` (session boot id); `/undo [n]` now consumes only the current session's turns, `/undo --all` also consumes other sessions'/subagents' turns and pre-ownership manifests (a hint appears when other sessions' turns exist). Interrupted undos complete first: consumption is journaled atomically BEFORE any file write, so a crash mid-`/undo` re-runs safely (idempotent before-image restores, never an extra turn). Per-file restore failures are listed (corrupt-blob / missing-blob / outside / oversized) instead of reported as success. Prune keeps a 40-manifest floor per owner with a 200-manifest global cap.
- **LSP crash recovery** — after a language-server crash the agent transparently restarts it (within cooldown/restart caps) and re-opens the documents it had open, so the after-edit diagnostics feedback loop continues instead of going permanently silent.
- **MCP resilience** — a crashed or failed MCP server now cools down (30 s) before reconnect attempts instead of respawning on every call; a restarted HTTP server (404 on the old session id) is transparently re-initialized once and the call replayed; transient 429/503s are retried with backoff.
