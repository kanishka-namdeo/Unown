### Fixed

- **fresh-clone: supervisor-launched services missed the root `.env` — the bridge ran keyless** — bun auto-loads `.env` only from a process's own CWD, and the two mini-services run from `mini-services/<name>/`. `bun run agent:start` delivers the root config by parsing and exporting it (scripts/start.ts), but any other supervisor that just runs the service `dev` script from the service dir (the sandbox's `.zscripts/dev.sh` scans `mini-services/*/package.json` and launches `bun --hot`) started the bridge WITHOUT `BRIDGE_UPSTREAM_KEY`: `/health` still reported the upstream reachable (its probe is unauthenticated), while every chat failed upstream 401 — and the engine booted on defaults, unaware of `.env` overrides. `scripts/install.ts` now symlinks the repo-root `.env` into both service dirs (`mini-services/<service>/.env → ../../.env`; idempotent — a correct symlink is left alone, a stray regular file that would silently shadow the root config is replaced; non-fatal warning where symlinks are unavailable, e.g. Windows without Developer Mode, where the launcher export path still covers `agent:start`). Verified live on a fresh clone: symlink + supervisor restart → bridge `/health` reports `upstreamKeyIsSet:true`, engine registers `zai-bridge/kimi-k2.5` from the root `.env`. `mini-services/AGENTS.md` now documents both delivery paths.
- **`bun run lint` was red on a fresh clone while CI's lint job stayed green** — the root script lints the whole tree (`eslint .`) and tripped over the vendored mermaid bundle (`scripts/vendor/mermaid-11.16.1.min.js`: 5 `no-this-alias` errors inside minified code), while CI's lint job runs `bunx eslint src` only — the documented local gate and the enforced gate had silently diverged, so the first `bun run lint` on a clean checkout failed. `scripts/vendor/**` (third-party minified bundles, same status as `node_modules`) is now in the eslint ignore list; `bun run lint` passes on a clean tree and remains consistent with CI's `src` scope.

- **task tool: structured outputs (oh-my-pi port)** — any task call (single or `tasks[]` batch item) can pass `output_schema` (a JSON Schema) + `schema_mode` (`permissive` default | `strict`): the subagent's final reply is parsed as JSON (bare, fenced, or one object inside prose) and validated by a new dependency-free JSON Schema subset validator (`src/jsonschema.ts` — types, properties/required/additionalProperties, items/prefixItems, enum/const, numeric/string/array/object constraints, anyOf/oneOf/allOf/not, local `$ref` to `#/$defs`/`#/definitions`; depth-capped at 64 with a schema-error escape hatch instead of stack overflow). An invalid reply triggers up to two corrective re-runs whose prompt quotes the exact path-annotated defects back to the child (`$.findings[0].severity: expected low | medium | high, got "critical"`); a still-invalid reply lands as a visible permissive warning over the raw text, or as an error in strict mode. A valid reply is returned to the parent as a fenced JSON block — the typed data IS the report. Malformed caller schemas fail pre-spawn (`checkSchemaShape`) — no paid run on a broken contract. Pinned by `test/jsonschema.test.ts` (38) + `test/cli/task-structured.test.ts` (3 spawn-level goldens: valid flow, retry-then-permissive-warning with the child re-spawned exactly 2 extra times, strict failure).
- **task tool: worktree fan-out isolation (muse code port)** — `worktree_isolation: true` (single or batch item) runs the subagent in its own git worktree at HEAD (`<repo>/.unown/worktrees/<id>`, `git worktree add --detach`), so parallel writers never collide with each other or with uncommitted work. Contract (muse's, kept verbatim in spirit): opt-in and FAIL-CLOSED — outside a git repo, or with `UNOWN_WORKTREE_ISOLATION=0`, the spawn is a typed rejection and the child NEVER runs in the shared tree; cleanup policy `remove_if_clean` (a clean, commit-less tree is removed and pruned; a dirty or committed tree is KEPT and its path reported for merge — nothing merges automatically); lifecycle journaled append-only to `.unown/worktrees/registry.jsonl` (spawned/kept/removed/quarantined with base commit + policy); every git probe runs with repository hooks disabled (private empty `core.hooksPath` + `--no-optional-locks` + stripped `GIT_*` env — muse ADR 33406's hostile-repo-config class, portable to Windows where `/dev/null` hooks tricks are not); a tree whose state cannot be proven after a crash is quarantined (renamed aside), never deleted. The checkpoints extension's self-healing `.unown/.gitignore` now also ignores `worktrees/`. Pinned by `test/worktree.test.ts` (9, real-git lifecycle incl. the hostile-hook and vanished-tree quarantine cases) + 2 spawn-level goldens (KEPT tree end-to-end with the file in the tree and the parent repo untouched; not-a-repo typed rejection).

- **opt-in mint cascade: local-draft + remote-repair task authoring (H10)** — `PI_MINT_CASCADE=1` switches the mint pipeline's shared draft-authoring step (both sources — failed-run mining and curriculum variants — route through it) to the topology verified in E8: a small local model drafts on the UNCHANGED authoring prompt, grammar-constrained by a json_schema (`llm.ts chatJson/chat` gain an optional `responseSchema` that attaches `response_format {type:json_schema, strict:true}` — with a portability fallback: an upstream 400 while a schema was attached retries once without it, logged on the bus as `llm:schema-fallback`); the existing `validateDraft()` gate decides — a valid draft proceeds with NO remote call at all, an invalid one gets exactly ONE remote repair call on the regular mint model (`PI_MINT_MODEL_ID`/`PI_MODEL_ID`, no schema — the remote upstream doesn't enforce schema keywords, E7/H9) carrying the authoring transcript + the invalid draft + the validator error (the E8 repair text, sync-commented); a repair that still fails validation lands in the existing discarded path with a cascade-aware reason.
