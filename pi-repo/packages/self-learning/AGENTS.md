# Self-learning engine (pi-repo/packages/self-learning/)

## Purpose

Unown's core transformation: the self-learning layer that turns the vendored pi coding agent into an agent that finds its own weaknesses, fixes them, and remembers what worked. Implements the five mechanisms: tiered memory (`memory.ts`), self-improving harness with statistical ship gate and retention auto-unship (`harness.ts`), routing/background jobs (`router.ts`), AutoDreaming with canary gate + dream-minted Agent Skills (`dream.ts`, `skills.ts`), and 6-layer hooks (`hooks.ts`, `termhooks.ts`). Task minting (`mint.ts`) keeps the harness fed: real failures (or, when the suite saturates, LLM-authored harder curriculum variants) become new capability-eval tasks that graduate into the regression suite once passing. Also provides the `unown` terminal agent (`cli.ts`, `term.ts`, `tools.ts`) and the REST+SSE API the dashboard consumes (`server.ts`).

This package is Unowned (modified from upstream pi-mono); sibling packages (`ai`, `agent`, `tui`, `server`, …) are upstream code — their rules live in `pi-repo/AGENTS.md`.

## Local Contracts

- Booted by `mini-services/agent-service` (port 3030) — never run standalone for the stack; `bun run agent:engine` for dev.
- Environment (defaults in parentheses): `PI_AGENT_PORT` (3030), `PI_BRIDGE_URL` (http://127.0.0.1:3031 — served by llm-bridge), `PI_MODEL_ID` (model id registered with pi; current: kimi-k2.5), `PI_PROVIDER` (zai-bridge), `PI_SELFLEARNING_DATA` (`<repo>/data/self-learning`), `PI_SELFLEARNING_DB` (`<repo>/db/selflearning.db`), `PI_DREAM_GATE` (on; `0` disables the dream canary gate), `UNOWN_HOME` (~/.unown — terminal-agent state), `UNOWN_ENGINE_URL` (http://127.0.0.1:3030), `UNOWN_STRICT_HOOKS` (off; `1` = sandbox-grade hooks in terminal sessions), `UNOWN_MAX_MINTED_TASKS` (8 — max ACTIVE minted tasks before `task-mint` skips).
- Model registration: `llm.ts` writes `models.json` into the generated pi agent dir (`data/self-learning/pi-agent-dir/`) from `PI_MODEL_ID`/`PI_BRIDGE_URL`. Local template contract (in `runner.ts`, `term.ts`): input `["text","image"]` (VLM enabled), contextWindow 131072, maxTokens 8192. The terminal agent's copy lives at `~/.unown/agent/models.json`.
- Terminal session tools (`tools.ts`, wired via `extensionFactories` in `cli.ts`): the bundled `unown-tools` inline extension registers the `todo` tool (session-entry-backed state, branch-correct), the `note` tool (mid-session notes delivered to the engine via `deliverTerminalNote`), the `task` tool (subagents: spawns `unown --mode json -p --no-session [--tools …] [--append-system-prompt <tmpfile>]` as a subprocess — agents are built-ins `general`/`explore` plus markdown definitions in `<project>/.unown/agents/*.md` and `~/.unown/agent/agents/*.md` with `name`/`description`/`tools` frontmatter), and the `fetch_url` tool (GET, HTML-stripped, 2 MB body cap). Commands: `/plan` (+ `--plan` flag + Ctrl+Alt+P) toggles plan mode (read-only toolset, bash allowlist via `isSafeCommand`, numbered `Plan:` extraction, approve-to-execute with `[DONE:n]` tracking), `/todos`, `/note`, `/agents`, `/learning`.
- Subagent contract: spawned with env `UNOWN_SUBAGENT=1` — the `task` tool is not registered inside subagents (no nesting), and their exit notes are tagged `[subagent]` in `buildTerminalNote` so AutoDream sees provenance. Subagent timeout 300 s, output cap 16 k chars, stderr cap 2 k.
- Starter Agent Skills (`skill-seeds.ts` → seeded by `ensureUnownAgentDir` into `~/.unown/agent/skills/`, never clobbering user edits): `unown-self-learning`, `verification-first`, `methodical-debugging`, `repo-exploration` (pi validates SKILL.md: lowercase-hyphen `name` ≤64 chars, `description` ≤1024 chars). Terminal sessions additionally discover per-project skills from `<project>/.unown/skills/` (passed as `additionalSkillPaths` from `cli.ts` only when the dir exists — the loader errors on missing paths).
- `cli.ts` flags: `-p/--print`, `--verbose`, `--mode json|text` (JSON event stream for subagent capture), `--no-session` (in-memory session manager), `--tools a,b` (restrict active tools), `--append-system-prompt <path>`, `--plan` (extension flag `plan`). Commands `setup` (dispatched before the generic parser — it owns its own flag grammar; see `setup.ts`) and `models` (see `setup.ts`). The memory `agentsFilesOverride` re-resolves `resolveTerminalMemory(cwd)` per session (re)new so AutoDream updates become visible without restarting the CLI. Every TUI/print session runs a pre-flight probe (`probe.ts`, skipped when `UNOWN_NO_PREFLIGHT=1` or `UNOWN_SUBAGENT=1`): unreachable endpoint or rejected credentials abort print mode with actionable guidance (exit 1, stderr only — stdout carries the JSON stream) and warn-and-continue in TUI mode. First run on a virgin `~/.unown` prints a banner pointing at `unown setup`.
- `setup.ts` — `unown setup` provider wizard + `unown models`. Presets (bridge/openai/openrouter/anthropic/dashscope/deepseek/custom) with endpoint/model defaults; interactive (TTY) or flag-driven (`--provider --api-key --model --base-url --force --list`; non-TTY without flags prints the flag usage). Writes a full-rewrite `models.json` (bridge mode keeps the placeholder/shared key inside it per the bridge contract; direct providers store the key in `auth.json` mode 0600) plus `defaultProvider`/`defaultModel` merged into `settings.json`, creating the agent dir when missing; verifies reachability and reports rejected keys as failures. `unown models` lists configured providers/models (default marked from settings) and, for loopback providers, the live `/v1/models` list with an allow-list cross-check.
- `probe.ts` — endpoint probes shared by doctor/setup/pre-flight: `probeOpenAiEndpoint` (GET `{baseUrl}/models`, classifies `unreachable` vs `auth` 401/403; other statuses count as reachable — some endpoints lack /models), `readAgentModelsFile`/`resolveActiveProvider` (settings `defaultProvider` wins, else first provider), `isLoopbackProvider`.
- `term.ts` agent-dir bootstrap: fresh `models.json` defaults to provider `zai-bridge`, model `kimi-k2.5` (the old `glm-4-plus` fallback was stale — also fixed in `runner.ts` MODEL_ID), apiKey `BRIDGE_API_KEY ?? "bridge-local"` (so a bridge shared secret keeps working), and a fresh `settings.json` pins `defaultProvider`/`defaultModel` (no first-run picker). `writeModelsJson` never clobbers existing files; `ensureUnownAgentDirInfo` exposes first-run state (`unownAgentDirInit`) for the banner and is idempotent within a process.
- API surface on :3030 is the dashboard contract — see `src/lib/AGENTS.md` for the endpoint list; changing an endpoint requires updating that doc in the same change.
- Task minting (`mint.ts`, router job `task-mint` every 30 min, manual `POST /api/tasks/mint`): mines the most recent FAILED run not yet minted from (Anthropic's "tasks from real failures" recipe), or — when the suite is saturated — asks the LLM for a harder curriculum variant of a random passing task (SEAgent-style). Pipeline: author draft → `validateDraft` (slug id, file-path safety, size caps, `*.test.mjs` + node:assert contract) → `selfCheckDraft` (verify script must FAIL cleanly against the seeded files in a fresh sandbox — syntax/module crashes reject the draft) → insert inactive (`origin='minted'`, `status='validating'`, `source_run_id` provenance) → validation run with the real agent → the task ACTIVATES as a capability eval only if the agent FAILS it (passes are discarded — honest outcome); infra-death marks discarded. `graduateTask` (called from the harness's baseline-passed branch) flips capability → regression and emits `task:graduated`; minted tasks only ever reach `regression` via graduation. `suiteStats()` feeds `kpis.suite` on the overview. Tasks-table columns `origin`/`status`/`source_run_id` are store migrations (defaults `seed`/`regression` — seeded tasks behave as before).
- Skill acquisition (`skills.ts`, hooked into `runProjectDream` after a successful consolidation): the LLM sees the consolidated memory + notes + the existing skill index and proposes ≤2 NEW skills per dream — recurring MULTI-STEP procedures only (single observations belong in memory). Proposals are validated (lowercase-hyphen name ≤64 chars, description ≤1024 chars, body 80–8000 chars) and deduplicated against on-disk `.unown/skills/` plus DB rows (ceiling 24 per project). Shipped skills are written to `<project>/.unown/skills/<name>/SKILL.md` (discovered by terminal sessions via `additionalSkillPaths`) and recorded in `skills` + `skill_versions` (version 1, dream provenance, `skill:minted` event). Rollback restores a prior version's file; retire removes the file and marks the row — retirement is manual only (the engine never deletes user files autonomously). Minting never throws into the dream path. API: `GET /api/skills[?project=]`, `GET /api/skills/:id`, `POST /api/skills/:id/rollback` {version}, `POST /api/skills/:id/retire`.
- Statistical ship gate (binding, not a tunable): a mined memory patch ships only after the candidate run AND a second confirmation run (fresh sandbox, same overlay) both pass — a non-replicating pass is rejected as noise and its evidence re-mined. Graduation on baseline-pass and the noise gate are part of the learning-integrity surface.
- Learning-integrity gates are binding behavior, not tunables to remove: ship gate (candidate run must pass in a fresh sandbox), dream canary gate (consolidation must re-pass the most recently passing task, else rolled back to status `gated`), retention check (later baseline failure auto-unships the improvement and rolls memory back), full version history (every tier write is versioned + attributable).
- Sandboxes: every harness/task run deploys a fresh isolated workspace, jailed exec with timeouts/output caps, sha256-pinned verification tests.
- OS-level sandbox (`src/bwrap.ts` + `native/bin/bwrap`): when bubblewrap is available, every engine sandbox command runs under the validated profile — whole rootfs read-only (fresh `/proc` `/dev`, `/sys` ro), `/home` `/run` `/tmp` `/var/tmp` private tmpfs (repo, `.env`, engine data invisible to task code), workspace bind-mounted at its real path, network + IPC namespaces unshared, caps dropped, `--die-with-parent`. Two integration points: `execInSandbox` wraps verify-script/exec commands directly, and `runner.ts` injects the generated wrapper (`pi-agent-dir/unown-sandbox-shell`) as the agent session's `shellPath` so every bash-tool call re-execs under bwrap. Env knobs (root `.env`): `UNOWN_OS_SANDBOX=0` disables (falls back to the TS path jail), `UNOWN_SANDBOX_NET=1` keeps the network shared, `UNOWN_BWRAP` overrides the binary path (default: vendored `native/bin/bwrap` — Debian trixie bubblewrap 0.12.0, provenance + sha256 in `native/README.md`). `unown doctor` reports availability. Known residuals (kernel 5.10 host): no pid namespace (fresh procfs in nested pidns is EPERM) — host pids are listed but signals to ancestor-userns processes are refused (verified); the workspace mount chain creates visible-but-empty ancestor dirs. Terminal-agent sessions are NOT OS-sandboxed (developer tool, needs full environment — same split as the hook policy).
- Runtime state (gitignored): `data/self-learning/` and `db/selflearning.db` — created/seeded on first boot (default memory tiers, five benchmark tasks: fizzbuzz, impl-debounce, map-limit, drop-right, fix-csv-parser; router jobs).
- Per-project memory: AutoDream consolidates terminal session notes into `<project>/.unown/memory/project.md`; notes queue offline in `~/.unown/notes/outbox/` and sync via the `note-sync` job / `outbox.ts`.
