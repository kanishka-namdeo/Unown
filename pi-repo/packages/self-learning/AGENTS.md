# Self-learning engine (pi-repo/packages/self-learning/)

## Purpose

Unown's core transformation layer and the only locally-owned package in the vendored pi monorepo: it turns the pi coding agent into a self-learning agent via the five mechanisms — tiered memory, a self-improving harness, routing, AutoDreaming + skill acquisition, and hooks — plus the `unown` terminal agent (CLI + TUI + session tools) and the detached engine (REST+SSE on :3030). ~147 source files; the largest single file is `tools.ts` (the "unown-tools" extension).

## Ownership

- Owns: everything under `pi-repo/packages/self-learning/` (`src/`, `test/`, `native/` — the vendored bwrap binary and tree-sitter grammars — and this doc). Sibling packages (`agent`, `ai`, `client`, `coding-agent`, `evals`, `protocol`, `server`, `session-backends/sqlite-node`, `telemetry`, `tui`) are upstream pi code governed by `pi-repo/AGENTS.md`.
- The engine's serving surface is booted by `mini-services/agent-service`; the bridge it talks to is `mini-services/llm-bridge`.

## Local Contracts

**The five mechanisms:**

1. **Tiered memory** (`memory.ts`, `memzero.ts`, `term.ts`, `budget.ts`, `memory-guide.ts`) — four tiers, most-specific-wins: `policy → project → user → local`, injected into every pi session as `<project_instructions>` blocks. Engine tiers: SQLite (WAL) is the authority — every write commits a `memory_versions` row in a `BEGIN IMMEDIATE` txn, then materializes the `.md` atomically (tmp+fsync+rename); reads self-heal file drift from the DB. The project tier runs on the Mem0 platform (in-process `mem0ai` OSS TS SDK; the tier file is a deterministic render; `## Manual notes` survives every re-render; the `project.provenance.json` sidecar records authorship). Terminal project memory (`.unown/memory/project.md`) is file-is-truth, written atomically by dreams. Caps: `PI_MEMORY_MAX_TIER_CHARS` (48,000) + `PI_MEMORY_TOTAL_CHARS` (80,000) with oldest-rules-first degradation at injection.
2. **Self-improving harness** (`harness.ts`, `mint.ts`, `tasks.ts`, `runner.ts`) — baseline run in a fresh sandbox → on failure, mine the transcript for candidate memory rules → candidate run with patched memory → ship only if verified twice → regression sweep; shipped patches that later regress are auto-un-shipped (retention check). When the suite saturates, task minting converts real failures or LLM-authored curriculum variants into new tasks, which graduate into the regression suite once mastered (caps: `UNOWN_MAX_MINTED_TASKS` 8, 6 files / 12k chars / 40k total).
3. **Routing** (`router.ts`, `bus.ts`, `governor.ts`) — nine jobs: interval `harness-cycle` (10m), `auto-dream` (10m), `note-sync` (5m), `task-mint` (30m), `sandbox-gc` (15m), `db-retention` (24h), `watch-scan` (2m) + event `regression-on-ship`, `dream-check`. One scheduler tick serializes through a busy mutex (busy conflicts answer HTTP 409). Learning jobs consult the governor (rolling spend ledger `PI_ENGINE_MAX_CALLS_HOUR/TOKENS_HOUR/TOKENS_DAY` + upstream circuit breaker). Watchdog `PI_JOB_TIMEOUT_MS` (20 min). `JOB_DEFS` here is the source the landing page's `engine-data.ts` is generated from.
4. **AutoDreaming + skills** (`dream.ts`, `canary.ts`, `guard.ts`, `hoist.ts`, `skills.ts`, `localml.ts`) — Mem0-backed consolidation of session notes: terminal notes → each real project's `.unown/memory/project.md` (canary-gated for benchmark notes; a dream that breaks the last-passing task rolls back memory version AND platform event stream). Quarantined notes (`guard.ts`) never reach the extraction LLM (structural zero-extraction). Recurring multi-step procedures are minted as Agent Skills into `.unown/skills-staged/` — never auto-loaded; promotion into `.unown/skills/` is a human `mv` (the review point).
5. **Hooks** (`hooks.ts`, `termhooks.ts`, `bash-policy.ts`, `hooks-config.ts`, `adversary.ts`, `injection-scanner.ts`, `shield.ts`, `instruction-guard.ts`) — engine + terminal extensions enforcing guardrails at every layer: SessionStart, UserPromptSubmit, PreToolUse (bash deny-list + path jail + adversary reviewer + injection scanner), PostToolUse (syntax gate + auto-verify), Stop, SubagentStop; a user-configurable layer honors 13 events with five handler types (`command`, `http`, `mcp`, `prompt`, `agent`) via `.unown/hooks.json` (project file trust-gated). `instruction-guard.ts` denies in-session writes (tools AND bash redirects) to the instruction set: `AGENTS.md`/`CLAUDE.md` at any depth, `.unown/skills/**`, `.unown/memory/project.md` + provenance, hooks/permissions configs — verdict final, above the declarative permissions layer. Every decision is logged.

**Terminal agent** (`cli.ts` dispatch + HELP, `boot.ts` — the entry `bin/unown` AND the release binaries compile from, `term.ts`, `tools.ts`): interactive TUI + `-p` headless + ~27 management commands (the authoritative list is the HELP in `cli.ts`; the 2026-10-24 parity round added `unown import` — config migration from claude-code/codex/gemini/cursor/opencode, `import-config.ts` + `import-cli.ts` — and `unown worktrees list|remove`, `worktree-session.ts`). Headless guards (2026-10-24 CI round, `max-turns.ts` + `output-schema.ts`): a "turn" is ONE MODEL CALL (`message_start` per assistant message — `agent_start`/`agent_end` bracket the whole loop and are NOT turns); `--max-turns N` aborts the (N+1)th call through pi's ctx.abort (the Ctrl-C path — disposal, notes and exit semantics behave as an interrupted run), the envelope's `num_turns` counts completed turns and a capped run with an answer reports subtype success; `--output-schema <file>` fence-strips and validates the final answer with the task tool's own dependency-free validator, exit 3 on mismatch, refused with `--mode json`; print-mode exits: 0 success (a --max-turns cap with an answer is still 0 — `capped: true` is the signal) / 1 error-empty / 2 usage / 3 schema-invalid / 4 loop guard tripped (`tool-repetition.ts`, the 2026-10-24 parity round — the SAME tool called with the SAME arguments N times consecutively aborts, key-order canonicalized, envelope gains `loop_guard`). Session tools registered every session: `todo`, `note`, `task` (fresh-context subagents; agents in `.unown/agents/*.md`; the 2026-10-26 rounds 3-4 gave BOTH lanes a durable lifecycle journal at the git-toplevel `.unown/fleet/journal.jsonl` — sync children are lane-tagged, heartbeat via the internal `UNOWN_SYNC_HEARTBEAT` env, and every session boot sweeps orphans of crashed parents, `fleet-reaper.ts`, `UNOWN_FLEET_REAPER=0` disables both lanes), `ask_user_question`, `fetch_url`, `web_search` + `webfetch` (keyless provider chain + 10 keyed providers; SSRF-hardened, robots-aware), `lsp`, `browser` (CDP-direct Chromium automation with stealth + captcha tiers), `get_context_remaining`, `view_image`, git tools; `/context` (`context-viz.ts`) is the user-facing view of the same window; `/status` + `/diff` (`status-card.ts`, 2026-10-25) are the visibility pair — the one-glance card (version, session, model + thinking, permissions mode/source, memory tiers, engine, worktree, git) and the working-tree diff (`--stat` compact; 200-line cap). Post-edit auto-formatters (`formatters.ts`, two scopes: `~/.unown/agent/formatters.json` always trusted + `.unown/formatters.json` trust-gated) ride the PostToolUse augment lane after the syntax gate — fail-open, latched on failure. Session workflow (`sessions.ts` + `sessions-cli.ts`): export (`--format md` CommonMark-safe / `json` portable / `html` via pi's own `/export` renderer, all default-on secrets redaction — the HTML lane redacts the raw JSONL BEFORE rendering, since the renderer's syntax highlighting can split a secret across spans) + BOTH stores (user `~/.unown/agent/sessions` cwd-filtered + project `.unown/sessions` imports; `unown-home.ts` owns the home resolution) + the 2026-10-25 completion round: `sessions delete <id|name> [--force]` / `rename <id|name> <new-name>` (strict multi-match refusal via `findSessionTargets` — never resume's newest-wins guess on same-named duplicates; delete refuses a <30 s mtime as live without `--force`; rename = `appendSessionInfoEntry`, the offline `/name`) and `list` carrying the session name. Bare `unown --resume` (TTY) opens pi's launch-time selector over both stores (`__resume_picker__` sentinel in `resolveLaunchSession`; pipes exit 2). parseArgs flag-adjacency: any dash-prefixed token after `--resume`/`--session` is the next flag, never a value. `--worktree [name]`/`-w` runs the session in a managed worktree (`worktree-session.ts` — exit interception, `.unown/` runtime state excluded from the dirty check; untouched tree removed, changed tree kept for review). Default active set: `read`, `bash`, `edit`, `write`, `ls` + `grep`/`find` when their binaries answer on PATH (`session-tools.ts`). Verify-first defaults: after every write/edit of a non-doc file the project's own check command runs PostToolUse and feeds failures back (`verify.ts`; `UNOWN_AUTO_VERIFY=0` disables). Split-view TUI, checkpoints + receipts ledger, session resume (`resume.ts`), project settings (`.unown/settings.json`, trust-gated, precedence CLI > project > user). Startup mark (`splash.ts`): an interactive boot plays the Unown script's eye in the header slot for ~1 s via `ctx.ui.setHeader()`, then restores pi's built-in header — `decode` (five forms → letters) on a machine's first session, latched in `onboarding.json` `tipsSeen`, and `eye` after. Invariants pinned by `test/splash.test.ts`: the `unown v…` wordmark is painted on every frame (the TUI capture lane waits on that literal), no row ever exceeds the terminal width (below its minimum the art is dropped, not wrapped), only theme tokens with no background fills, one play per process on `reason === "startup"` only, and suppression via `quietStartup` / `NO_COLOR` / `UNOWN_NO_SPLASH=1`.

**Install receipt in-session** (`install-surface.ts`, wired from `tools.ts` at `session_start`): the landing page's one-liner writes `~/.unown/install.json`, and the TUI now reads it back. The first session of an install prints a one-shot card — channel (standalone CLI vs source checkout), version, install root, PATH shim, install time, `from v…` after an update, and a closing line when this process runs an older build than the record describes — latched per recorded version in `onboarding.json`'s `installCardSeenFor`, which `tools.ts` writes only AFTER the card reached the notify pane (a context that swallowed it must not spend the one-shot). `/status` carries the one-line form (`install binary v0.0.16 (linux-x64)`, omitted when there is no record). While the agent dir has no provider the footer also carries `no model connected · /setup` through the same `setStatus` seam the turn meter uses: this is what replaced re-asking the first-run question (the gate's `created` latch stays), it never claims an absent model while the bundled bridge answers (`model: the bundled bridge · /setup for your own provider`), and a `models.json` that does not parse reads as unreadable rather than unconfigured. Both surfaces are cosmetic — TUI-only, never in a subagent, every UI seam guarded.

**Install-record parity** (contract, not a module): `install.json` (schema 1) is parsed by three readers — `install-layout.ts` (runtime), `public/install.sh` (POSIX, no bun available to help) and `public/install.ps1` — and all three accept it by the same rule: schema 1, mode `checkout` or `binary`, with the pre-release `source` spelling folded to `checkout`. Drift here is not cosmetic: a record one reader trusts and another refuses is an install that updates on one path and reports "cannot determine how this unown was installed" on another. Each installer therefore carries a read-only `--inspect` / `-Inspect` entry point, and `test/install-meta-readers.test.ts` drives the SHIPPED installers against records the runtime wrote (each side skips when its shell is absent).

**Always-on engine service** (`engine-service.ts`): `unown engine install|uninstall` own the per-user OS layer — systemd `--user` unit, launchd LaunchAgent, or a Windows logon scheduled task running `engine serve` — so the engine returns after a reboot with no agent invoked. The install/update lane makes it the DEFAULT on source installs (`scripts/install.ts` runs `engine install --auto`; `unown update` re-runs the installer, which also restarts a service-owned engine onto the new build). `--auto` skips, returning 0, when compiled, on an unsupported platform, in CI, under `UNOWN_ENGINE_AUTOSTART=0` or `UNOWN_NO_ENGINE_SERVICE=1`, or when the `$UNOWN_HOME/engine-service.disabled` marker exists; `unown engine uninstall` writes that marker (never silently re-added) and a manual `install` clears it. The generated definitions are pure builders pinned by `test/engine-service.test.ts` (restart-on-crash-but-never-on-clean-exit; spaces in paths quoted per the manager's parser — including the Windows task's CreateProcess argument string). Windows has a second lane: Task Scheduler's root folder is ACL-gated for standard accounts (live-caught — `Register-ScheduledTask` and `schtasks /Create` both answer Access denied unelevated), so a refused registration falls back to a hidden PowerShell watchdog registered under `HKCU\…\Run` (`%LOCALAPPDATA%\unown\engine-service.ps1`; logon start, non-zero exit → retry with capped backoff, exit 0 ends the loop, `cmd /c` appends the engine's raw UTF-8 to `.run/engine.log`). It is deliberately **WSH-free**: VBScript is a retired Windows feature (24H2 is the last release enabling it by default), and the pre-retirement `.vbs` launcher is removed by install/uninstall as a migration step. The Run value is capped at the documented 260 characters — an over-long path is refused with the reason instead of writing a truncated autostart. Two PowerShell generation rules are load-bearing: one statement per line (no implicit continuation), and restart settings through `New-ScheduledTaskSettingsSet -RestartCount/-RestartInterval` (direct `$settings.RestartInterval` assignment serialises `00:01:00`, which Task Scheduler rejects as out of range). The systemd unit keeps `StartLimitBurst/StartLimitIntervalSec` in `[Unit]` (systemd ignores them in `[Service]`) and doubles `%`/`$` in paths; a versioned bun (`Cellar/…`, asdf/mise installs, Scoop apps, Nix store) is swapped for the stable PATH shim or `BUN_INSTALL/bin/bun`; on macOS without a GUI session the plist is installed and the engine started for the current session, with an explicit "starts at your next desktop login" message instead of a false success.

**Engine health taxonomy** (`engine-probe.ts`, P0): every engine client distinguishes `ok` / `refused` / `unauthorized` / `occupied` / `incompatible` / `unreachable`. Only `refused` authorises `spawnEngineDetached`; a 401/occupied/incompatible/hung probe records `lastCause` in the crash-loop state without counting an attempt and publishes the TUI `blocked` state. `unown engine start` refuses a foreign engine; `stop` requires `--force --pid`, `restart` requires `--take-ownership`; `repair` gates on this data dir's lock/pid (a 401 engine is still live); `serve` exits 0 as a clean loser on an occupied port. `UNOWN_RUNTIME_DIR` isolates `engine.log`/`engine.pid`/the circuit/transition marker from a live engine. Pinned by `test/engine-probe.test.ts` + the blocked cases in the `engine-status`/`spawn-circuit`/`engine-cli` suites.

**Engine service** (`server.ts` :3030): REST+SSE API — `/api/overview`, `/api/events` (SSE), `/api/tasks` + runs, `/api/memory` + rollback, `/api/cycles` + improvements + dreams, `/api/skills`, `/api/hooks` (+ inbound webhook lane `/api/hooks/<32-hex>`, auth-by-URL, 64KB cap), `/api/notes` (413 over 20,000 chars), `/api/jobs` + trigger/toggle, `/api/automations` (routines CRUD + runs + event-dispatch), `/api/bridge`, `/api/webcache`. Auth (M7): Host-header allowlist (anti DNS-rebinding) + Origin enforcement + per-boot bearer token in `DATA_DIR/engine.token` (0600, written before port bind) — required on every `/api` request except preflights and `GET /` liveness; same-user clients auto-discover via `engineFetch`. A non-loopback bind with auth off refuses to boot. Single-instance lock; `PRAGMA quick_check` integrity gate; graceful drain.

**Sandbox** (`sandbox.ts`, `bwrap.ts`): every engine agent run deploys a fresh sandbox — boundary-aware path jail, hardened bash deny-list, timeout + 60k output cap, HOME pinned to the sandbox root; OS-level isolation via bubblewrap (Linux; the vendored binary) / seatbelt (macOS) / TS path-jail fallback (Windows). Engine sandboxes are offline by default (`UNOWN_SANDBOX_NET`).

**Automations/routines** (`automations.ts`, `routine-schedule.ts`, `hook-filter.ts`): five schedule kinds (cron / every / after / once / event) + retries, chains, active-hours, idle-only (reads the bridge's `lanes.lastInteractiveAt`), result webhooks, jitter. Event payloads reach dispatched runs framed as DATA, never instructions; the `routine.*` webhook namespace is reserved (external senders cannot forge chain triggers).

**Env contracts**: every knob is documented in the root `.env.example` (engine `PI_*`/`UNOWN_*`, bridge `BRIDGE_*`) and `docs/configuration.md` — keep all three in sync in the same change. Note the repo convention: defaults use `||` not `??` (`.env` ships empty `KEY=` values that bun auto-loads).

**Instruction-set security surfaces owned here**: `instruction-guard.ts` (write deny table), `check_instruction_chars`-aligned unicode lint core, `config-trust.ts` (project-config trust gate for `.unown/mcp.json`/`lsp.json`/`hooks.json` — REFUSE FIRST; approval pins a sha256 fingerprint; `UNOWN_TRUST_PROJECT_CONFIG=1` bypass for CI/headless), `permissions.ts` (granular allow/deny/ask; can only add restrictions).

## Work Guidance

- Upstream pi rules (`pi-repo/AGENTS.md`) bind edits here: erasable TypeScript syntax only in checked paths, no inline imports, no `any`, read files in full before wide-ranging changes, treat dep/lockfile changes as reviewed code.
- A CLI surface change (command/flag/env var) updates `cli.ts` HELP + `docs/usage.md` + `docs/configuration.md` in the same change; a `JOB_DEFS` change moves `engine-data.ts` (regenerate via `scripts/landing_claims.mjs`); a behavior change gets the CHANGELOG Agent Behavior entry + `docs/BEHAVIOR.md` update + pinning tests.
- The engine DB is the authority for engine tiers; never hand-edit materialized tier files while the engine is up.
- Failed harness cycles auto-recover — do NOT restart the engine to fix them (see `.unown/skills/recover-failed-cycle/SKILL.md`).
- `bunx biome check --write` on changed files in `pi-repo/` before committing (project memory workflow rule).

## Verification

- `bun test test/` from this package root — the engine unit suite (172 test files; order-independent via the `test/_env.ts` preload that redirects DB/data to a scratch tmpdir, points the bridge at a dead port, isolates `UNOWN_HOME`).
- `PI_TEST_SCOPE=integration bun test test/integration/` — the integration suite (real server + mock bridge).
- Live gates: `UNOWN_MEMORY_LIVE=1 bun test test/memory-live.test.ts`; `UNOWN_MEMORY_POISON=1 bun test test/memory-poison.test.ts`; `UNOWN_BROWSER_LIVE=1` for the browser lanes.
- Version consistency: `bun bin/unown --version` === root `package.json` version (CI asserts it).
- Install-record parity: `bun test test/install-meta-readers.test.ts` runs the SHIPPED `public/install.sh --inspect` / `public/install.ps1 -Inspect` against records `writeInstallMetadata` produced, plus both mode-change refusals (release base pointed at a dead port, so no case can install anything; each side skips when its shell is absent). This is the only gate that can catch the three readers drifting apart.
- Sandbox legs: `bash scripts/bwrap_smoke.sh` + `bun scripts/verify_sandbox.mjs` before committing sandbox changes.
- Smoke: `curl -s -H "Authorization: Bearer $(cat data/self-learning/engine.token)" localhost:3030/api/overview` → `ok:true`; `bun bin/unown doctor` green.
