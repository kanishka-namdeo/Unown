## Fixes (all shipped this round)

1. **F1+F2**: `plan-model` and `max-turns` are now registered extension flags (`pi.registerFlag`, string type) — the flag lane is live and the swallowed "Unknown option" diagnostic is gone. The runtime's collected diagnostics are now surfaced: the print lane prints them on stderr (mirroring pi's own `reportDiagnostics`), the TUI lane passes them into `InteractiveMode`'s existing `startupDiagnostics` renderer.
2. **F2 (timing)**: `planTurnBudget` is now computed at CALL time (flag values are applied after the factory runs), so the 60% `--max-turns` cap engages.
3. **F3**: an explicitly-set `UNOWN_PLAN_TURN_BUDGET=0` now really disables the pressure (unset stays 15 — `Number("")` is 0, so the unset case is guarded exactly like `planThreshold`'s raw/NaN pattern; caught by the round's own new test before it could ship).
4. **F4**: the boot/resume lane runs the same side effects as `/plan` — the entry notice (shared `planModeOnNotice` helper, both wordings) and the todo-overlay suspension.
5. **F5**: the non-interactive setup lane probes the endpoint ONCE up front and registers the discovered catalog alongside the chosen model (chosen first, user specs preserved, best-effort specs for extras), reusing that one probe for the spec gate, the extra-spec pass and the reachability print. **Verified live**: models.json now carries all 6 served models.
6. **F6**: the stay-loop fix, two halves: (a) a STAYED outcome sets `planGateStayedForRun`, which keeps BOTH the agent_end fallback gate AND the in-tool gate quiet for the rest of the run — the in-tool gate answers with a soft "do NOT re-offer now, end your turn" text instead of opening a dialog; `agent_start` (the user's next message) re-arms everything. REJECTED-with-feedback keeps re-arming per turn on purpose (the fallback gate still rescues a model that revises but forgets to re-offer). (b) the stayed tool-result text now explicitly instructs the model to end its turn. **Verified live**: no re-offer within 45 s after dismissal; a user message re-arms and the approval completes.
7. **F7**: the approved-plan instruction now names the discipline explicitly — "flip the seeded todo tasks by id … do not create new todos for the same work" — in both the exit_plan_mode approved text and the fallback lane's unown-plan-execute message. **Verified live**: seeds=1, creates=0, updates≥1, "Plan complete" fires.
8. **F8**: HELP and the `/plan` description tell the truth (V3 default + kill switch; the in-TUI editor).
9. **F9**: the s2 scenario anchors match the rendered strings ("Plan ready — ", "User has approved your plan"/"Approved plan (").
10. **F10**: the settings hub's permission-mode help no longer lists `plan`; the GAP-REGISTER and pt-1 scoring lines point at the real scorer surface.
11. **F11 (partial, the test-isolation half)**: the round's test file restores the global fleet-activity latch (fires `agent_settled` after each `agent_start` and resets the symbol in afterAll). The load-dependent watchdog/fleet timing flakiness is filed for the owning lane — not caused by this round (both suites pass in isolation and the full suite is green in this round's final runs).
12. **The plan-model not-found fallback is now visible in print mode** (stderr warning; it used to be TUI-only).

## Hand-off notes

- The upstream is a metered free tier (~20 RPM): the full V3 orchestrator (audit + specialists) on a fresh scratch project can exceed 5 minutes under throttling. The matrix lane's gate timeout defaults to 480 s and is `MATRIX_GATE_TIMEOUT`-overridable.
- Any future extension flag MUST be registered by the consuming extension in the same change that parses it in cli.ts — pi's loader contract makes unregistered flags dead-on-arrival, and the runtime diagnostics now make that VISIBLE instead of silent (the regression guard this round wished it had).
- The fleet-activity global latch (`Symbol.for("unown-fleet-activity")`) is process-global: any test that fires `agent_start` on a wired extension MUST pair it with `agent_settled` (or reset the latch) or `isFleetBusy()`-dependent tests in the same process fail.
