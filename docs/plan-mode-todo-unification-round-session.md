## Research baseline (done before any edit)

- **Codebase audit** (subagent, very thorough): every plan-mode and todo surface mapped — `tools.ts` (plan-mode state, toolset switch, `updateStatus`, `runPlanApprovalDialog`, `approvePlanExecution`, `exit_plan_mode`, the agent_end fallback gate, resume replay), `addons/todo.ts` (tool, overlay widget, store, seed bridge, `/todos`), `addons/todo-core.ts` (reducer), `mission.ts` (derived progress), `plan.ts` (`markCompletedSteps`).
- **Competitor lane** (subagent, live web research with sources):
  - **OpenAI Codex** hard-separates the two: the `update_plan` todo tool is **rejected during Plan mode** at the tool layer with the error *"update_plan is a TODO/checklist tool and is not allowed in Plan mode"* ([codex-rs/core/src/tools/handlers/plan.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/plan.rs)), the [plan.md collaboration template](https://github.com/openai/codex/blob/main/codex-rs/collaboration-mode-templates/templates/plan.md) states the same at the prompt layer, and maintainers closed the complaint as by-design ([codex#18669](https://github.com/openai/codex/issues/18669)).
  - **Gemini CLI**: the plan-mode tool allowlist deliberately excludes `write_todos` ([plan-mode doc](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/plan-mode.md)) — planning writes only the plan file.
  - **Claude Code**: plan mode is a permission mode ending in an approval dialog; the task list is ONE separate live surface fed by the task tools — the plan is never rendered as a second checklist ([permission-modes](https://code.claude.com/docs/en/permission-modes.md), [interactive-mode](https://code.claude.com/docs/en/interactive-mode.md)).
  - **pi** upstream: a plan-mode extension bug parsed free text into todos and fired the exit gate ([pi#8503](https://github.com/earendil-works/pi/issues/8503)) — the same plan/todo confusion family.
  - Duplication-family bugs in the wild: [codex#54528](https://github.com/openai/codex/issues/54528) (each update appended a new full TODO card), [codex#35118](https://github.com/openai/codex/issues/35118) (footer step badge desynced from the plan dropdown), [claude-code#23224](https://github.com/anthropics/claude-code/issues/23224) (duplicated `/todos` output), ink's Static-vs-live replay traps.
- **Consensus design rule** across all five agents: plan and todos are different things — the plan is a *user-approved proposal artifact*, the todo list is *live execution state*; exactly one progress surface may be visible at a time; the plan→todo handoff happens once, atomically, at approval.

## Fix plan (milestones; each = commit + push)

- **M1 (single surface)**: remove the `plan-steps` widget registration from `updateStatus` — the footer status chip (`plan 2/5`) stays, the todo overlay becomes the only checklist above the editor.
- **M2 (one-list semantics at approval)**: `seedForegroundTodos` gains replace semantics — clear the foreground todo list, seed the approved steps, refresh the overlay immediately, append one replayable state entry (resume shows exactly the seeded list).
- **M3 (no todos while planning)**: move `todo` from `PLAN_MODE_TOOLS to `PLAN_MODE_DISABLED_TOOLS` (with `edit`/`write`/`task`); the plan-mode system prompt states the rule Codex-style; golden toolset pin updated.
- **M4 (bidirectional progress sync)**: `[DONE:n]` tag completions flip the matching seeded todo; todo-tool completions flip the matching plan step — one visible list, two input paths, always in agreement (chip, mission panel, completion note, overlay).
- **M5 (single echo in the fallback gate)**: the model-facing `unown-plan-execute` instruction becomes `display: false`; the user sees the approved plan once plus the live Todos panel.
- **M6 (tests)**: widget-capture assertions in the plan-mode suite (no `plan-steps` ever mounts; approval mounts the seeded `unown-todos`; re-approval replaces; `[DONE:n]` flips the seeded todo; the plan-mode toolset excludes `todo`); golden CLI pin updated; todo replace-semantics unit tests.
- **M7 (docs/DOX/record/push)**: usage.md §Plan mode, BEHAVIOR.md §Plan Mode V2, self-learning AGENTS.md plan paragraph, GAP-REGISTER P-06 resolution cell, CHANGELOG [Unreleased] (+ Agent Behavior), landing regeneration, all local gates, real-user verification, DOX closeout.
