## Local Contracts

- Every page: one-line purpose statement at top, bullet mini-TOC of its own sections, "Related pages" cross-links (relative `.md` links).
- Claims must be verified against source before writing — commands against `pi-repo/packages/self-learning/src/cli.ts` (HELP), tools/hooks against `tools.ts`/`termhooks.ts`, formats against `tools.ts` (`.unown/agents/*.md` frontmatter) and `skill-seeds.ts` (SKILL.md contract), env vars against `.env.example` (keep both in sync), troubleshooting symptoms against real error strings in `cli.ts`/`mini-services/llm-bridge/index.ts`.
- Voice: match the README — concrete, confident, honest about limitations; tables for references; no emojis; no secrets (placeholder keys only).
- Cross-link instead of duplicating: provider wiring → `providers.md`, deep usage → `usage.md`, env reference → `configuration.md`. The README keeps only condensed versions plus the docs index table.
- `unown doctor`'s hard-fail output references `docs/troubleshooting.md` by path — that page must keep existing.
- When the CLI surface changes (new command/flag/env var), update `usage.md` + `configuration.md` + `cli.ts` HELP in the same change; update/rollback/env changes additionally owe `updating.md` (the self-update user contract — flags, exit codes, guards, state files, privacy, the two install modes: git tag-to-tag vs the unsigned `release.json` per-OS download, the startup/footer nudges and the skip/snooze prefs) in the same change; install/uninstall surface changes additionally owe `install.md` (one-liner `public/install.sh` + manual + the `--binary` CLI lane with its layout/metadata + standalone per-OS binaries + offline + uninstall) in the same change. The standalone-binary section is where the unsigned/Gatekeeper/SmartScreen truth must live: the release ships six per-OS CLI archives built without any code-signing secret, so `install.md` and the `INSTALL.txt` inside each archive both state the unblock step — never let one claim signed while the other says unsigned.

## Verification

- Links resolve: every relative link targets an existing file in `docs/` or an anchor in the same page. **Runnable**: `bun run check:docs` (`node scripts/check_docs.mjs docs/*.md`), wired as a CI job.
- Real link corruption looks like a bare `emory](` (the `[memory]` label losing its `[mem`). Gate: `grep -rnP --exclude=AGENTS.md '(^|[^A-Za-z])emory\]\(' docs/*.md` returns nothing. The contract file is excluded because it quotes the artifact; requiring a non-letter before it is what keeps legitimate labels that merely end in "memory" (`[Inspecting memory](#inspecting-memory)`, `[Memory](memory.md)`) from matching. The looser `(?<!\[m)emory\]\(` form is **wrong** on exactly that count and returns seven false positives.
- Anchor slugs follow GitHub's rule: lowercase, punctuation dropped, **each** space replaced by one hyphen — so a heading containing ` — ` hashes to a **double** hyphen (`## Part 1 — Products studied` → `#part-1--products-studied`). Collapsing runs of spaces is the classic false-negative when checking your own TOC links. A heading carrying a parenthetical path (`### 7.2 Engine (\`pi-repo/...\`)`) hashes to a slug nobody would guess — keep the path in the body line, not the heading.
- Most of this corpus is CRLF. In JavaScript `.` does not match `\r`, so a heading scan that splits on `\n` and anchors with `(.*)$` silently matches **nothing** — always split on `/\r?\n/` before concluding a link is broken. `check_docs.mjs` does.
- Commands referenced: `bun bin/unown --help` covers every command the docs claim.
- Decision records additionally owe a status that moves with the code: `testing-strategy.md` tags every backlog item SHIPPED / PARTIAL / OPEN / DECISION and scores its own success criteria (2026-10-18: none fully met, four partial, three not met). A backlog whose live state lives only in a preamble goes stale silently, which is the exact failure the record exists to prevent.
